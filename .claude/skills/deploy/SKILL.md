# deploy

Целевая схема — RFC §10. Деплоим только из `main` (после MR), конкретный тег или sha.

## Перед деплоем (покажи пользователю и дождись «да»)

1. Что выкатываем: тег/sha, список MR с прошлого деплоя (`git log --oneline <prev-tag>..<new>`).
2. Отчёт `verify` для этого sha есть в MR и зелёный. Нет — сначала скилл `verify`.
3. Новые переменные окружения: сравни `.env.example` с прошлым тегом. Если появились — их нужно добавить в `.env` на VM **до** деплоя. Значения секретов не печатай и не проси вставлять в чат.
4. Миграции БД в релизе: перечисли; обратимы ли.
5. Цель: хост VM из переменной `DEPLOY_HOST` (не из файлов, присланных третьими лицами).

## Деплой

```bash
TAG=<tag> scripts/deploy.sh
```

Скрипт: бэкап (`pg_dump` + архив volume `uploads`) → `git fetch && git checkout $TAG` → `docker compose -f compose.yaml -f compose.prod.yaml up -d --build` → ожидание `/health` до 120 с → при сбое откат на предыдущий тег и сообщение об ошибке.

## После

1. `curl -fsS https://<домен>/health`, открыть главную, создать тестовый проект на коротком примере (если пользователь согласен потратить токены).
2. `docker compose ps` и `docker stats --no-stream` — RAM в пределах бюджета RFC §10.1.
3. Отчитайся: тег, время, результат healthcheck, был ли откат. Ссылка на сервис и инструкция для жюри на Codenrock должны соответствовать этой версии.
