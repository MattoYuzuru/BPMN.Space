# new-endpoint

Слои и правило зависимостей — RFC §5.6: `api → services → (domain, llm, ingest, infra)`, `domain` без I/O. Контракт — RFC §5.8.

## Шаги

1. **Сначала проверь, нет ли похожего.** Поищи по `backend/app/api` и `services` — если логика отличается на пару процентов, расширь существующий сервис, а не копируй (jscpd и `cleaner` это всё равно найдут).
2. **Схемы** запроса/ответа — `backend/app/api/schemas/<ресурс>.py`, Pydantic v2, без бизнес-логики. Имена полей — `snake_case`, даты — ISO 8601, id — UUID.
3. **Сервис** — `backend/app/services/<ресурс>.py`: вся логика здесь, зависимости (сессия БД, клиенты) приходят параметрами.
4. **Роут** — `backend/app/api/v1/<ресурс>.py`: тонкий, только валидация, вызов сервиса, маппинг ошибок в HTTP-коды. Префикс `/api/v1`. Длинные операции (LLM-прогоны) — `202` + id + SSE, не держим запрос минутами.
5. **Конфиг** — новые настройки только в `backend/app/config.py` и `.env.example`. Никаких URL, ключей и магических чисел в коде.
6. **Тесты:**
   - юнит-тест сервиса (LLM — записанные фикстуры, не живая модель);
   - интеграционный тест роута через `httpx.AsyncClient` на тестовой БД;
   - негативные случаи: 404, 422, конфликт статусов.
7. **Миграция**, если менялась схема БД: `alembic revision --autogenerate -m "<что>"`, проверь сгенерированное глазами.
8. **Контракт:** `make openapi` → `docs/api/openapi.json`; перегенерируй TS-клиент фронтенда (`npm run gen:api` во `frontend/`).
9. **Документация:** таблица эндпоинтов в RFC §5.8 / `docs/architecture`, если появился новый ресурс.
10. `make check`, затем скилл `verify`.
