# prompt-eval

Промпты — код продукта: `backend/app/llm/prompts/`. Golden set — `evals/` (RFC §8). Живая модель тратит деньги — перед полным прогоном спроси пользователя.

## Шаги

1. **Базовая линия.** Найди последний отчёт в `evals/reports/` для текущей модели и промпта. Если его нет — сначала прогони `make eval` на текущем состоянии.
2. **Гипотеза.** Сформулируй одну: «модель путает XOR и AND, потому что в few-shot нет параллельной ветки». Одно изменение за прогон — иначе непонятно, что сработало.
3. **Изменение:**
   - промпт/few-shot — правь шаблоны в `prompts/`, не строки внутри кода;
   - модель — только через `.env` (`LLM_MODEL`, `LLM_OUTPUT_MODE`), код не трогаем; если модель не держит json_schema — `LLM_OUTPUT_MODE=prompted`.
4. **Быстрая проверка** на 2–3 кейсах: `make eval CASES=<id,id>`.
5. **Полный прогон:** `make eval`. Метрики (скрипт в `evals/`):
   - F1 по участникам/дорожкам, задачам, шлюзам (по нормализованным именам);
   - доля схем, валидных по XSD и без ошибок bpmnlint;
   - доля цитат `source.quote`, найденных в источниках (галлюцинации);
   - среднее число repair-кругов, латентность p50/p95, токены и ₽ на кейс.
6. **Сравнение** с базовой линией таблицей. Регрессия по любой метрике > 5 п.п. — изменение не принимаем без обсуждения.
7. **Фиксация:** отчёт в `evals/reports/<дата>-<модель>-<коротко>.md`; если поменялся основной промпт или модель — обнови фикстуры записанных ответов для юнит-тестов (`make record-fixtures`) и упомяни в MR.
