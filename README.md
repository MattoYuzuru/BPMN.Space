# Архитектор BPMN-диаграмм

Веб-приложение для аналитиков: помогает превратить описание бизнес-процесса в основу BPMN 2.0, уточнить недостающие условия и открыть схему для редактирования. Архитектура и границы текущей реализации описаны в [`docs/rfc/0001-architecture.md`](docs/rfc/0001-architecture.md).

## Быстрый запуск

Нужны Docker с Compose, Node.js и `uv` для локальной разработки.

```bash
cp .env.example .env
make setup
make up
```

Откройте [http://localhost:8080](http://localhost:8080). По умолчанию используются mock-провайдеры; для локального запуска без API-ключей этого достаточно.

Для разработки без Docker используйте `make dev-backend` и `make dev-frontend` в отдельных терминалах. Полный список проверок и команд: `make help`.

## Внешние AI-провайдеры

Ключи указываются только в корневом `.env`, который исключён из Git. Инструкция по DeepSeek и Deepgram: [`docs/backend/подключение-провайдеров.md`](docs/backend/подключение-провайдеров.md). Не добавляйте ключи в исходники, issues, merge requests или скриншоты.

## Деплой команды

Рабочая VM, подготовка SSH-доступа, однократная загрузка production-конфигурации, обновление и откат описаны в [`docs/deployment.md`](docs/deployment.md). Деплой запускается вручную из проверенного commit SHA в `main`; GitLab CI/CD и раннеры не используются.

## Работа в команде

Сначала прочитайте [`AGENTS.md`](AGENTS.md). Все изменения отправляйте отдельной веткой и Merge Request в `main`. Перед MR выполните `make verify`; перед деплоем — только после попадания проверенного коммита в `main`.
