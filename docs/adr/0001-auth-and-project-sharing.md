# ADR-0001. Cookie-сессии и роли доступа к проектам

- Статус: принято
- Дата: 2026-10-04
- Связано: RFC-0001 §§5.7–5.8

## Контекст

Нужны аккаунты по email и паролю, приватные проекты владельца и совместная работа по ссылке. Участник с ролью редактора должен войти в аккаунт. В браузере требуется безопасная сессия с возможностью отзыва. В проекте уже используется FastAPI и async SQLAlchemy.

## Варианты

| Вариант | Плюсы | Минусы |
|---|---|---|
| Самостоятельно написать пользователей, хеширование пароля и токены | Полный контроль | Высокий риск ошибок в чувствительной к безопасности логике, больше кода для сопровождения |
| FastAPI Users | Готовые маршруты регистрации, входа, выхода и профиля; async SQLAlchemy; cookie- и DB-сессии | Библиотека в режиме сопровождения, почтовые сценарии требуют отдельного backend |
| Внешний identity-provider | Делегирование паролей и восстановления | Новый внешний сервис и настройка, зависимость от сетевой доступности и тарифов |

## Решение

Использовать FastAPI Users `15.x` с PostgreSQL адаптером, Argon2-хешированием паролей и случайными DB-backed сессиями в HttpOnly cookie на 14 дней. В БД записывать только SHA-256 хеш сессионного токена. Флаг `Secure` см. [ADR-0002](0002-rate-limits-and-secure-cookies.md); изменяющие API-запросы защищены double-submit CSRF cookie и заголовком `X-CSRF-Token`.

Проект хранит владельца, редакторов и ссылки двух ролей. `viewer` открывает данные только через bearer-ссылку и не может менять проект. `editor` должен зарегистрироваться или войти и отдельно принять ссылку; после этого его доступ хранится как членство в проекте. Ссылки случайные, в БД сохраняется только SHA-256 хеш; срок ссылки обязателен (редактор — 7 дней по умолчанию, максимум 30; viewer — 30 и 365), владелец может отозвать ссылку. Удалять проект и управлять доступом может только владелец. Чужой проект скрывается ответом `404`.

Регистрация пока не требует подтверждения email, а восстановление забытого пароля не включено: для обоих сценариев нужно подключить и проверить почтовый сервис. Ограничение частоты — в [ADR-0002](0002-rate-limits-and-secure-cookies.md). FastAPI Users остаётся в режиме сопровождения, поэтому при существенном расширении требований стоит повторно оценить библиотеку или внешний identity-provider.

При включённой авторизации весь API, кроме `/auth/*`, `GET /examples`, `/health` и ссылок `/shares/{token}`, требует входа. Открытыми на чтение остаются только демо-проекты из сида (`public_read_only`, миграция `0006` закрыла остальные). Проекты, созданные до миграции и не имеющие владельца, остаются приватными. Перед включением авторизации на существующей базе владелец должен сопоставить их с аккаунтами и выполнить явное backfill `projects.owner_id`; миграция не открывает старые рабочие данные всем зарегистрированным пользователям.

## Последствия

- Новые пользовательские проекты требуют PostgreSQL и создаются с `owner_id` текущего пользователя.
- Демонстрационные проекты доступны вошедшим пользователям только для чтения; гости видят только ссылки `viewer`.
- Пароли, исходные токены сессий и исходные токены share-ссылок не сохраняются в открытом виде.
- Все изменяющие API-запросы при включённой auth требуют CSRF cookie/header.
- Для production необходимо включить HTTPS, задать `APP_ENV=production`, сохранить PostgreSQL volumes и выполнить миграцию `0005_auth_and_sharing`.
