# ADR-0002. Ограничение частоты запросов и Secure-cookie

- Статус: принято
- Дата: 2026-10-04
- Связано: [ADR-0001](0001-auth-and-project-sharing.md), RFC-0001 §5.8

## Контекст

С включённой авторизацией API стал публичным: любой может подбирать пароли, создавать аккаунты и гонять платные вызовы (Deepgram, DeepSeek). Лимитов нигде не было. Одновременно `Secure` у cookie был жёстко привязан к `APP_ENV=production`, так что без HTTPS сессия в production не работала бы, а включить флаг отдельно было нельзя.

## Варианты

| Вариант | Плюсы | Минусы |
|---|---|---|
| Лимиты на reverse proxy (Caddy) | Не трогает код | Нужен сторонний модуль Caddy, нет лимита «на аккаунт» |
| Redis + библиотека лимитов | Работает на нескольких воркерах | Новая инфраструктура ради одного процесса |
| Скользящее окно в памяти процесса | Ноль зависимостей, видит аккаунт | Счётчики сбрасываются при рестарте, не масштабируется на несколько воркеров |

## Решение

- Лимиты в памяти процесса (`backend/app/api/ratelimit.py`), потому что backend работает одним воркером. Они только против спама и подбора, поэтому щедрые и не считаются свойством продукта. Значения в `config.py`: весь API — 600 запросов в минуту на IP; вход и регистрация — 20 в минуту на IP; прогон, помощник, расшифровка и загрузка файла — 60 в минуту на аккаунт и 120 в минуту на IP (чтобы лимит нельзя было обойти регистрацией новых аккаунтов). Ответ — `429`, заголовок `Retry-After`, `detail` на русском. `RATE_LIMIT_ENABLED=false` отключает всё (в тестах так).
- IP берётся из последнего значения `X-Forwarded-For`: его дописывает наш Caddy, а левые значения клиент подделать может.
- `SESSION_COOKIE_SECURE` (пустое значение — по `APP_ENV`: `production` и `prod` включают `Secure`) управляет флагом у сессионной и CSRF-cookie. Явное значение нужно, пока HTTPS не настроен (`false`), либо если TLS завершается снаружи при другом `APP_ENV` (`true`).

## Последствия

- При переходе на несколько воркеров или инстансов лимиты придётся вынести в общее хранилище или на proxy.
- Если за Caddy стоит ещё один proxy, последний адрес `X-Forwarded-For` будет его адресом: лимит станет общим на всех. Тогда нужно настраивать доверенные proxy.
- Production требует HTTPS для входа (Secure-cookie). На стенде без HTTPS задайте `SESSION_COOKIE_SECURE=false` в серверном окружении; с HTTPS ничего задавать не надо.
