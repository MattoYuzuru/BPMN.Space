# ADR-0003. Присутствие по SSE, история по неизменяемым версиям BPMN

- Статус: предложено
- Дата: 2026-10-04
- Связано: RFC-0001, совместный доступ к проекту

## Контекст

Пользователь должен видеть, кто сейчас открыл общий проект, кто сохранил схему и что изменилось. Проект уже хранит полные XML-версии BPMN и показывает их в панели истории. Сейчас у версии нет автора, а счётчики диффа не называют элементы. Редактор bpmn-js работает с одним XML-документом; одновременное редактирование пока не согласуется автоматически.

## Варианты

| Вариант | Плюсы | Минусы |
|---|---|---|
| SSE для присутствия, существующие версии для истории | Малое изменение; доступ через ту же сессию и роли; можно открыть старую версию | Присутствие ограничено одним процессом сервера; одновременные правки требуют отдельного решения |
| Yjs/Hocuspocus для всей доски | Основа для совместного редактирования | Присутствие и CRDT нужно связать с командами bpmn-js и XML, разрешить конфликты модели, проверить валидность BPMN; намного больше работ |
| Периодические запросы для присутствия | Простота | Задержка и лишние запросы на каждую открытую доску |

## Решение

Список присутствующих передаётся отдельным SSE-потоком. Состояние краткоживущее, отдельно от BPMN, с повторной проверкой доступа. Несколько вкладок одного аккаунта считаются одним человеком. Сохранённая версия получает адрес почты автора на момент создания; старым версиям автор не приписывается. Панель истории сравнивает два неизменяемых XML и называет добавленные, удалённые и переименованные элементы. Кнопка «Открыть» показывает выбранную старую версию в режиме просмотра.

## Последствия

- При нескольких процессах backend понадобится общий реестр присутствия (Redis pub/sub или аналог); текущий production запускается одним процессом. Данные присутствия после перезапуска не восстанавливаются.
- Полноценное одновременное редактирование не появляется. Для него отдельная работа: транспорт операций, разрешение конфликтов и проверка BPMN после слияния. Присутствие не обещает, что чужой курсор или несохранённый XML виден другим.
- История покрывает сохранённые версии схемы. Историю каждого изменения источников и вопросов следует проектировать отдельно как журнал действий.
- Снимок адреса почты даёт историческую атрибуцию; если политика удаления персональных данных потребует анонимизации, нужен отдельный механизм её применения к истории.
