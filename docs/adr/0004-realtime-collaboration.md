# ADR-0004. WebSocket-события комнаты и проверка базовой версии BPMN

- Статус: принято
- Дата: 2026-10-05
- Связано: RFC-0001 §§ 5–6, RFC-0002, ADR-0001, ADR-0003

## Контекст

`main` уже содержит SSE-присутствие аккаунтов и неизменяемые BPMN-версии с автором. Приложение
размещено одним FastAPI-процессом за Caddy. SSE подходит для списка участников, но не для частых
двусторонних курсорных сообщений. Схема редактируется в bpmn-js как полный XML; автоматического
слияния команд и встроенного протокола конфликтов в приложении нет.

## Варианты

| Вариант | Плюсы | Минусы |
|---|---|---|
| Сохранить только SSE и добавить POST для курсора | Переиспользует текущую инфраструктуру | Двусторонние частые события создают лишние запросы; неестественная обработка reconnect |
| WebSocket для комнаты + существующий SSE-список | Живое двустороннее присутствие; минимум риска для текущей функции | На двух backend-инстансах нужна межпроцессная рассылка |
| Yjs/Hocuspocus как каноническая BPMN-модель | Даст CRDT-примитивы и готовую awareness-модель | Нужно отобразить bpmn-js, BPMN DI/moddle, связи, undo/redo, ACL и проверку XML на CRDT-граф; отдельный runtime и миграция данных |

## Решение

Оставить существующий SSE endpoint и добавить проектную WebSocket-комнату в FastAPI. Соединение
получает короткоживущий одноразовый билет через REST; account-билет выдаётся после проверки сессии и
роли, guest-билет — после проверки активной viewer-ссылки. Постоянный share token не передаётся в URL
WebSocket. In-memory hub используется только для ephemeral presence и рассылки в текущей одно-процессной
конфигурации.

Каждая ручная BPMN-фиксация обязана указывать `base_version_id`. Сервис проверяет его под текущей
блокировкой строки проекта. Устаревшая запись возвращает `409 stale_version`, не создаёт версию и
передаёт id головы для resync. Событие новой версии публикуется только после commit. Такой контроль
не выдаёт полные XML-снимки за CRDT: он гарантирует, что конкурентные действия обнаруживаются и не
затирают сохранённые данные.

Долгие прогоны остаются под существующим ограничением `uq_runs_active_project`; их этапы
распространяются участникам комнаты. Для нескольких backend-процессов позже добавить Redis Pub/Sub,
не перенося туда источник истины проектов, версий и прогонов.

## Последствия

- Сохраняется текущий API доступов и не вводится новая зависимость типа Yjs/Hocuspocus до проверки
  интеграции с bpmn-js.
- Первая версия поддерживает живые курсоры, присутствие и обмен уже сохранёнными версиями, защищая
  от потери чужой правки. Если два человека начали от одной версии, локальная правка проигравшего
  требует безопасного resync/сохранения черновика.
- Полное конкурентное слияние операций, undo/redo и BPMN-графа — отдельный PoC/RFC.
- При изменении REST-контракта обновить `docs/api/openapi.json` и сгенерированные TypeScript-типы.
- Ticket, курсоры и пользовательские сокеты краткоживущие; обновление/отзыв прав закрывает доступ.
