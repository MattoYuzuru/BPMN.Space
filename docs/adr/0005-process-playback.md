# ADR-0005. Локальное воспроизведение BPMN и отдельная модель длительностей

- Статус: принято для воспроизведения; параметры бизнес-времени предложены в RFC-0003
- Дата: 2026-10-06
- Связано: [RFC-0003](../rfc/0003-process-playback-and-timing.md), RFC-0001 §2.4, GitLab #16

## Контекст

Пользователь включает «Таймлайн процесса» и видит скорость, но не видит движения: включение
плагина не запускает стартовое событие. Требуется наглядное прохождение, включая параллельные
ветви. При этом XML должен открываться в обычных BPMN-редакторах, а проигрывание не должно
создавать сохранённые версии и конфликты с совместным редактированием.

Реальные сроки задач сейчас не извлекаются и не хранятся. Скорость экранного токена не даёт
оснований вычислять SLA или длительность заявки.

## Варианты

| Вариант | Последствия |
|---|---|
| Самостоятельный обход задач по порядку XML | простая анимация, но неверные XOR/AND, join и циклы |
| Использовать установленный token-simulation и явно управлять запуском | штатная BPMN-семантика, небольшой объём интеграции |
| Сразу внедрить серверный движок исполнения и календарей | требует новой модели времени, входов сценария и доказательств; избыточно для текущей UX-проблемы |

## Решение

Использовать `bpmn-js-token-simulation` в текущем ленивом редакторе. Единственный подходящий
старт запускается сразу; несколько стартов требуют выбора. Ветвления и ожидания исполняются
библиотекой, UI показывает реальное состояние и доступные действия. Проигрывание локально,
отдельно от команд редактирования, XML-сохранения и WebSocket-событий комнаты.

Runtime-токены и подсветка не входят в экспорт. Импорт новой версии сбрасывает прогон. Чек-лист
онбординга отмечается после фактического запуска, а не после включения режима.

Длительности, календари и происхождение оценок имеют отдельную задачу. Предлагаемый формат
переносимых параметров — типизированный `extensionElements` с версией и собственным namespace;
его внедрение требует moddle descriptor, строгой серверной проверки и roundtrip-тестов. В этой
итерации собственный namespace в XML не добавляется.

## Последствия

- Видимое воспроизведение не требует новой БД, REST API или серверного процесса.
- Изменения коллеги в совместном редактировании сохраняют свои гарантии и транспорт.
- Генератор графового IR v1 теперь поддерживает XOR/AND и циклы (#20, ADR-0006); его поднабор уже, чем возможности проигрывания импортированного BPMN. Воспроизведение OR и событийного шлюза не означает, что генератор умеет их создавать.
- Сторонним редакторам передаётся обычный BPMN; совместимость будущих metadata проверяется отдельно.
- UI прямо отделяет экранную скорость от модельного бизнес-времени.
