# ADR-0007. Сжатые изменения XML и ограниченные цепочки версий

- Статус: принято
- Дата: 2026-10-06
- Связано: RFC-0001 §2.4, RFC-0002 «Сохранение схемы и конфликты»

## Контекст

Ручное сохранение после паузы 1,5 секунды создавало полный XML-снимок и метаданные.
На сервере измерено 93 версии, 744 КБ с индексами, средний ручной XML 14,9 КБ.
PostgreSQL сжимает его до примерно 3,1 КБ, но каждая правка дублирует почти весь XML.
Список истории и подготовка LLM-контекста также читали XML всех версий.

## Варианты

| Вариант | Последствия |
|---|---|
| Удалять старые версии или группировать автосохранения | теряется точная история; неприемлемо |
| Хранить внутренние команды bpmn-js | требует фронта; привязка к внутренним объектам и версии библиотеки |
| Собственные семантические операции над BPMN | полезно для будущего аудита действий, но нужен полный охват XML/DI/расширений |
| Хранить точные изменения UTF-8 XML и контрольные снимки | независимость от фронта, сохранение каждого байта; выбранный вариант |

## Решение

API по-прежнему принимает и возвращает полный XML. Репозиторий хранит `BVS1`:
сжатый zlib снимок, либо `BVD1`: сжатую замену диапазона байтов предыдущего XML.
Префикс/суффикс определяются за линейное время, без квадратичного сравнения документов.
Дельта выбирается только при экономии более 128 байт против сжатого полного снимка.
Генерация модели всегда создаёт независимый снимок; ручная цепочка имеет максимум 20 дельт.
UUID предыдущей версии, глубина и SHA-256 результата хранятся отдельно.

При чтении одной версии загружается ограниченная цепочка (не более 21 версии), проверяются
проект, порядок номеров, глубина и SHA-256 каждого результата. Несовпадение вызывает явную
ошибку, а не выдачу частично восстановленной схемы. Сжатие и восстановление идут в рабочем
потоке, чтобы не блокировать WebSocket/event loop.

Список истории и карточки проектов не загружают XML/payload. LLM-контекст восстанавливает
XML только текущей версии. Идентичный XML с актуальной базой возвращает прежнюю версию:
новая строка, событие realtime и запись о ручной правке не создаются. Устаревшая база по-прежнему
даёт 409. Номера, авторы, цитаты, допущения, проверки и все старые версии сохраняются.

Миграция добавляет формат, не переписывая большие таблицы. Старые XML читаются непосредственно.
Отдельная повторяемая команда сжимает их пакетами под той же блокировкой проекта, что save/build.
Если старая версия уже служит базой новой дельты, она преобразуется только в независимый снимок.
Обратная команда разворачивает версии от новых к старым; прерывание безопасно.

## Последствия

Операции хранения пока означают точные изменения байтов, а не пользовательские действия
«переместил блок»: такой аудит потребует отдельного семантического контракта. `diff` API остаётся
прежним счётчиком элементов. Метаданные (report/trace/lanes) остаются независимыми JSONB-снимками,
чтобы списки и маркеры читались непосредственно. Дедупликация этих метаданных — отдельная задача
при подтверждённом росте их объёма.

Старый релиз не умеет читать packed XML. Перед откатом приложения необходимо остановить записи
и выполнить `--restore` кодом нового релиза. Alembic downgrade отказывается удалять packed-данные
до восстановления. Скрипт деплоя выполняет эту подготовку перед автоматическим откатом на старый формат; при ошибке
восстановления останавливает откат, сохраняя данные для диагностики.
Пагинация существующего списка требует отдельного изменения API/фронта и здесь не вводится.
