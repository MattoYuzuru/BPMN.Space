# ADR-0013. Протокол Responses у совместимого провайдера

- Статус: принято
- Дата: 2026-11-12
- Связано: [ADR-0011](0011-user-llm-credentials.md), [RFC-0004](../rfc/0004-agent-mode.md),
  [RFC-0005](../rfc/0005-full-model-capacity-and-cost.md)

## Контекст

Совместимый провайдер (`openai_compatible`) умел только Chat Completions. Шлюзы подписки
ChatGPT (личный OpenAI Buffet владельца, `https://openai-buffet.keykomi.com/v1`) и новые серверы
OpenAI принимают только Responses API: `POST /v1/responses`, а Chat Completions отвечают
`501 use_responses_api`. Ключ такого шлюза нельзя было подключить вовсе:

- провайдер «OpenAI» игнорирует адрес и отправляет ключ шлюза на `api.openai.com` — `401`;
- «Совместимый с OpenAI» проходит проверку (`GET /models`), но первый прогон падает на `501`.

Шлюз подписки строже официального API: требует `store: false` и историю массивом `input`,
не принимает роль `system` (нужен `instructions`), отвергает `max_output_tokens`,
`temperature` и `previous_response_id` явной ошибкой `400 unsupported_parameter`.

## Варианты

| Вариант | Плюсы | Минусы |
|---|---|---|
| Отдельный провайдер `openai_responses` | Видно в списке провайдеров | Протокол смешан с поставщиком; справочник возможностей, цены и проверки удваиваются |
| Автоопределение по `501` | Ничего не выбирать | Неявно; первый запрос оплачивается и падает; хрупко на чужих серверах |
| **Протокол — поле ключа совместимого провайдера (`wire_api`)** | Протокол — свойство адреса, как `wire_api` у Codex CLI; поставщики и справочник не меняются | Пользователь выбирает протокол при добавлении ключа |

## Решение

**Данные.** `user_credentials.wire_api` (миграция `0027`): `chat_completions` или `responses`,
только у `openai_compatible` (CHECK). `NULL` у старых строк — Chat Completions. Протокол, как и
адрес, задаётся при добавлении ключа; сменить — удалить ключ и добавить заново. Модель оператора —
`LLM_WIRE_API` (по умолчанию `chat_completions`).

**Адаптер.** `OpenAIResponsesClient` (`llm/openai_responses.py`) наследует транспорт
`OpenAICompatibleClient`: закреплённый IP и проверку адреса (ADR-0011), потолок ответа, повторы
и классы ошибок. Меняется только форма:

- системный промпт — `instructions`, задача — сообщение в `input`, `store: false`, без стрима;
- JSON-режим — `text.format = json_object`; уровень профиля — `reasoning.effort`;
- изображения и PDF — части `input_image`/`input_file` (PDF только при `pdf_input`);
- инструменты — `function` с `strict: false` (схемы инструментов не строгие); вызовы —
  `function_call`, результаты — `function_call_output` с тем же `call_id`;
- рассуждение запрашивается зашифрованным (`include: reasoning.encrypted_content`) и
  повторяется в следующем ходе через `ConversationMessage.provider_blocks`, как подпись
  `thinking` у Anthropic; блоки без шифртекста и чужих провайдеров не повторяются;
- статус `incomplete` — обрезка (`OutputTruncatedError`) или отказ (`content_filter`),
  `failed` — ошибка; usage — `input_tokens`/`output_tokens`/`cached_tokens`.

**Согласование параметров.** `max_output_tokens`, `temperature`, `reasoning` и `include`
отправляются, а на `400` с явным отказом (`code: unsupported_parameter` или «unsupported» в
тексте) и именем параметра клиент один раз повторяет запрос без него и до конца прогона его не
шлёт. Остальные `400` и отказ от обязательных полей не обходятся. Так один адаптер работает и с
официальным API, и со шлюзом подписки, не зная его имени.

**Возможности модели.** `GET /models` того же сервера уточняет окно (`context_window`), уровни и
умолчание рассуждения (`supported_reasoning_levels`, `default_reasoning_level`) и изображения
(`input_modalities`). Описание запоминается в процессном справочнике с ключом по хосту адреса:
каталог одного сервера не меняет одноимённую модель другого. Без описания — осторожные
умолчания совместимого провайдера (уровень не отправляется).

**Подсказки.** Chat-клиент на `404/405/501` с упоминанием Responses отвечает «добавьте ключ
заново с протоколом Responses»; Responses-клиент на `404/405/501` — наоборот.

## Последствия

- Интерфейс: поле «Протокол API» у «Совместимый с OpenAI» в обоих диалогах ключей; в списке
  ключ с Responses помечен «Responses API». API: `wire_api` в создании и ответе
  `/me/llm-credentials` и `/me/credentials`.
- Официальный провайдер «OpenAI» остаётся на Chat Completions: переход на Responses для него —
  отдельное решение (цены и справочник не затронуты).
- Лимит ответа на шлюзе подписки не действует (шлюз его отвергает): обрезка ловится по статусу,
  стоимость по ключу совместимого провайдера по-прежнему не считается (`cost_usd=null`).
- Стрим, `previous_response_id` и хранение ответов на сервере не используются.
