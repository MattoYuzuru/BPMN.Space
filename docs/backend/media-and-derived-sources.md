# Записи и производные источники

Как сервер обрабатывает аудио и видео и как устроено дерево материалов. Исходное решение по
записям — [ADR-0012](../adr/0012-long-documents-and-media.md) п. 4 (пределы, ffmpeg, сегменты,
повторы); дерево материалов — шаг 3 [RFC-0006](../rfc/0006-tools-connectors-and-derived-sources.md).
Этот документ описывает текущее поведение; ADR остаётся записью решения.

## Что создаёт загрузка записи

`POST /projects/{id}/sources/file` с `.mp3 .wav .ogg .opus .m4a .flac .aac .webm .mp4 .mov .mkv`
пишет файл на диск потоком (`MAX_MEDIA_BYTES`) и в одной транзакции создаёт два источника:

| Узел | Поля | Текст |
|---|---|---|
| Исходный файл | `kind=file`, `origin=user`, `trust=primary`, `file_name`, `size_bytes`; после обработки `duration_sec` и `media` (`has_audio`, `has_video`) | нет: в модель не идёт |
| «Расшифровка: <название>» | `kind=text`, `origin=derived`, `trust=extracted`, `parent_id` записи, `derivation` | строки `[мм:сс] реплика` |

`derivation` расшифровки: `capability=speech_to_text`, `provider` из `STT_PROVIDER`
(`mock`, `deepgram`), `model` (`nova-3` у Deepgram, у mock — нет), `params` (`segment_sec`,
`block_sec`, формат звука, был ли ffmpeg; после обработки — `duration_sec` и `language`),
`cost_usd` (пока `null`: провайдер стоимость не сообщает), `created_at`.

API возвращает исходный файл; оба узла видны в `GET /projects/{id}` плоским списком, дерево
строится по `parent_id`. Счётчик источников проекта считает только исходные материалы.

## Статусы и сбои

Оба узла сразу `processing`. Фоновая обработка (`SourceService.process_file` →
`_process_media`): `ffprobe` (длительность, звук, видео; обложка mp3 видео не считается) →
ffmpeg режет звук на сегменты → STT с ограниченной параллельностью и одним повтором → склейка
`[мм:сс]`. Итог записывается точечным `patch` обоих узлов под блокировкой проекта и только
пока они в `processing`:

- успех — запись `ready` с длительностью и дорожками, расшифровка `ready` с текстом;
- сбой (нет звуковой дорожки, сегмент не расшифрован после повтора, нет речи, превышен
  `MAX_TEXT_CHARS`, ffmpeg недоступен) — **оба** `failed` с одной причиной; дорожки записи
  сохраняются, если ffprobe успел их прочитать;
- рестарт сервера во время обработки — оба `failed` (как документы, ADR-0012);
- расшифровки к началу обработки нет — STT не вызывается, запись `failed` с причиной «Расшифровка записи удалена до окончания обработки».

Аналитик может вписать текст в неудавшуюся расшифровку: она становится `ready` с
`edited_by_human=true`, а запись выходит из `failed`. Без ffmpeg работает только mock-STT
на небольшом файле (одним блоком `[00:00]`); дорожки тогда неизвестны (`media` с `null`).

Голосовые заметки с микрофона (`POST /transcriptions` → `POST /sources/text`, `kind=voice`)
не меняются: это один источник `origin=user`, текст проверил аналитик.

## Правка, выключение, удаление

- `PATCH /sources/{id}` с новым текстом производного источника ставит `edited_by_human=true`
  (тот же текст — не правка). Ревизий нет: правка перезаписывает текст ИИ, а цитаты на
  изменённые места перестают находиться так же, как у любого правленого источника.
  Ревизии и пересвязывание цитат — задача #34 (RFC-0006, шаг 7).
- У записи своего текста нет: правка `content` записи — `422`. Название править можно.
- Выключение записи (`active=false`) выключает её производные, включение — включает.
  Производный узел можно выключить отдельно.
- Удаление записи удаляет производные: в PostgreSQL — составной FK с `ON DELETE CASCADE`,
  в in-memory режиме — так же явно; файлы удаляются после фиксации. Удаление расшифровки
  оставляет запись, но пока расшифровка `processing`, удалить её нельзя (`409`): распознавание
  уже идёт и оплачивается — удаляется запись целиком или после окончания. ffprobe, ffmpeg и STT
  одной записи идут одной задачей под общим семафором `MEDIA_MAX_CONCURRENT_JOBS`.
- Создать источник с `parent_id` вручную нельзя: `POST /sources/text` отклоняет лишние поля
  (`422`), производные создаёт только сервер, а сервис проверяет, что родитель — источник
  того же проекта.

## Контекст прогона

Модель читает расшифровку, а не запись: правила отбора и уровни доверия —
[generation-quality.md](generation-quality.md#какие-источники-видит-модель-и-уровни-доверия-rfc-0006).
Хеш снимка источников совместим с прогонами, запущенными до миграции 0016
([persistence.md](persistence.md)).

## Не сделано

Кеш производных по хешу `(parent, capability, provider, model, params)`, перебор ключей по
возможностям, кадры видео и `vision`, OCR страниц, плеер с перемоткой к таймкоду, ревизии
производных (#34). Старые записи, загруженные до 0016, остаются одним источником с текстом.
