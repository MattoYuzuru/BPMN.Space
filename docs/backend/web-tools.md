# Веб-поиск и чтение страниц

- Дата: 2026-11-04
- Статус: реализовано в ветке `feature/wave-3-web-tools`: адаптеры `web_search`/`web_fetch`,
  сервис инструментов агентного режима и каталог провайдеров по ключам пользователя. Вызовы
  инструментов моделью (`complete_with_tools`) появятся в волне 4 — агентном режиме
  ([RFC-0004](../rfc/0004-agent-mode.md)); этот документ описывает готовый контракт и границы.
- Связано: [RFC-0006](../rfc/0006-tools-connectors-and-derived-sources.md) (шаги 1, 2, 6),
  [каталог провайдеров](../research/tool-providers-2026-11.md), [ADR-0011](../adr/0011-user-llm-credentials.md),
  [подключение провайдеров](подключение-провайдеров.md), [MCP для внешних агентов](mcp.md)

## Зачем

Аналитику нужен регламент, который лежит на сайте компании, или отраслевая новость с датой.
Модель просит «найди» и «прочитай страницу», а не «вызови Tavily»: возможность закрывает любой
подключённый ключ, выбор делает маршрутизатор по приоритету. Результаты — **данные, а не
инструкции**: страница не меняет проект, её текст проходит те же проверки, что и остальные
источники.

## Как пользователь подключает ключи

1. Настройки → «Инструменты» → карточка «Поиск в интернете» или «Чтение страниц».
2. «Добавить ключ»: провайдер, название (необязательно), ключ. Сервер проверяет ключ дешёвым
   запросом провайдера и сохраняет зашифрованным; открытый ключ в ответах не возвращается.
3. «Где взять ключ» и бесплатный уровень — из каталога `GET /api/v1/me/tool-catalog`; данные
   проверены 04.11.2026 и отдаются вместе с датой (`checked_on`).

Поддержанные провайдеры (есть адаптер в коде):

| Возможность | Провайдеры в коде | Проверка ключа |
|---|---|---|
| `web_search` | Tavily, Brave Search, Exa | поиск с одним результатом (один кредит/запрос); у Brave и Exa — так же |
| `web_fetch` | Jina Reader, Firecrawl | Jina: чтение `https://example.com`; Firecrawl: `GET /v1/team/credit-usage` без кредитов на страницы |

Ключ модели Claude тоже закрывает поиск и чтение — но серверными инструментами модели
(`$10` за 1000 поисков, `web_fetch` читает только адреса из разговора), а не этими адаптерами.
В каталоге такие провайдеры помечены `model_covers=true` и `supported=false`: интерфейс не
предлагает их как рабочий ключ.

В каталоге также перечислены провайдеры без адаптера (ElevenLabs, AssemblyAI, Yandex и другие):
это подсказки на будущее, у них `supported=false`.

## Как модель видит инструменты

Сервис — `backend/app/services/web_tools.py`. Возможности привязаны к `Capability.WEB_SEARCH` и
`Capability.WEB_FETCH`, имена инструментов для модели — `search_web` и `read_url`
(`domain/capabilities.py`).

### `search_web(query, recency?)`

```json
{
  "status": "ok",
  "query": "согласование заявки",
  "provider": "tavily",
  "cached": false,
  "results": [
    {
      "title": "Регламент согласования",
      "url": "https://example.com/reg",
      "snippet": "Заявка уходит на согласование",
      "published_at": "2026-10-30T00:00:00+00:00",
      "source": "tavily",
      "trust": "external"
    }
  ]
}
```

- `recency_days` — необязательная свежесть: Tavily получает `time_range`
  (`day/week/month/year`), Brave — `freshness` (`pd/pw/pm/py`), Exa — `startPublishedDate`;
  от 1 до 365 дней.
- `limit` — от 1 до 10, по умолчанию 5; выдача без дат допустима (у части страниц даты нет).
- Дедупликация по нормализованному адресу: якорь и метки слежения (`utm_*`, `gclid`, …)
  отбрасываются. Уже показанные в этом прогоне ссылки повторно не выдаются.

### `read_url(url)`

```json
{
  "status": "ok",
  "url": "https://example.com/process?utm_source=mail",
  "canonical_url": "https://example.com/process",
  "title": "Процесс согласования",
  "text": "# Процесс\n\nЗаявка согласуется за три дня.",
  "published_at": "2026-10-27T05:00:00+00:00",
  "fetched_at": "2026-11-04T12:00:00+00:00",
  "provider": "firecrawl",
  "truncated": false,
  "cached": false,
  "trust": "external"
}
```

- `canonical_url` — канонический адрес из метаданных провайдера (аналог `rel=canonical`);
  если провайдер его не сообщил — нормализованный запрошенный адрес.
- `published_at` — дата публикации, если провайдер её сообщил; `fetched_at` — дата получения
  по часам приложения (для провенанса).
- `text` — markdown/plain основного содержимого, без меню и рекламы; длиннее
  `MAX_PAGE_CHARS` (200 000 символов) обрезается с `truncated=true`.

Сервис не создаёт источники сам: агентный режим (волна 4) превращает результат в производный
источник `origin=derived`, `trust=external` с `derivation` (capability, provider, параметры,
дата) — как требует RFC-0006. Узел дерева материалов создаёт агент, поэтому повторный прогон
сможет переиспользовать его из кеша производных (по хешу), а не платить провайдеру снова.

## Пределы и поведение

- Таймаут запроса к провайдеру — 30 с (`WEB_REQUEST_TIMEOUT_SEC`); дальше маршрутизатор
  повторяет `transient` по общим правилам (`CAPABILITY_MAX_ATTEMPTS`, `Retry-After`).
- Предел размера ответа: 2 МБ для поиска, 8 МБ для страницы; больше — класс `unsupported`.
- Выдержка результата — 400 символов, текст страницы — 200 000; выдача — 10 ссылок максимум.
- Кеш прогона (`WebToolsCache`): поиски по `(запрос, свежесть, лимит)` и прочитанные страницы
  по нормализованному адресу; повторный вызов не платит провайдеру дважды и помечается
  `cached=true`. Кеш живёт в памяти прогона и не является кешем производных из RFC-0006.
- Кеш ограничен: 32 поиска и 32 страницы на прогон, дальше вытесняется самый старый.

## SSRF и чужие адреса

Адаптеры ходят только на фиксированные адреса провайдеров (`api.tavily.com`,
`api.search.brave.com`, `api.exa.ai`, `r.jina.ai`, `api.firecrawl.dev`); адрес самой страницы
сервер не скачивает — читает провайдер. Тем не менее `read_url` проверяет адрес до вызова:

- только `http(s)`, без логина и пароля в адресе;
- отклоняются `localhost`, имена с суффиксами `.local`, `.localdomain`, `.internal`, `.home`,
  `.lan`, `.corp` и служебные `metadata.google.internal`/`instance-data`;
- отклоняются литералы закрытых сетей: loopback, private, link-local (включая метаданные
  облака `169.254.169.254`), CGNAT, multicast, `0.0.0.0` — та же проверка, что в
  SSRF-защите моделей (ADR-0011).

Так закрытые внутренние адреса не уходят третьей стороне и не подменяются метаданными облака.
Закрытые страницы (Confluence, порталы за логином) этим способом не читаются: их приносит
внешний агент пользователя через MCP ([RFC-0007](../rfc/0007-external-agents-mcp.md)).

## Отказы и технические вопросы

Если возможность недоступна, исключение наружу не выходит: сервис возвращает структурный
результат (`status: unavailable|failed`, `reason`, `message`, `alternatives`, `done`,
`remaining`) по контракту `CapabilityOutcome` из RFC-0006. Причина — класс, а не текст
провайдера:

| Класс | Что значит | Что делает пользователь |
|---|---|---|
| `quota_exhausted` | закончилась квота ключа | пополнить или добавить второй ключ |
| `auth` | ключ отклонён | проверить ключ в настройках |
| `capability_missing` | ключа под возможность нет | добавить ключ или продолжить без веб-поиска |
| `unsupported` | провайдер не принял материал (размер/формат/адрес) | другой провайдер или без этого |
| `transient` | провайдер временно недоступен | повтор по общим правилам; вопроса не создаёт |

Отказ передаётся в `CapabilityIncidentSink` (`services/capability_incidents.py`) и становится
**неблокирующим** техническим вопросом проекта с действиями «Открыть настройки», «Повторить»,
«Продолжить без этого». Временный и фатальный сбои вопроса не создают — пользователь видит их
в ошибке источника и в настройках ключа. Агентный режим добавляет в допущения, что часть
материала не прочитана (`analysis_input_complete=false`).

## Каталог провайдеров в коде

`backend/app/services/tool_catalog.py` — данные с датой проверки (`CATALOG_CHECKED_ON =
2026-11-04`): возможность, подписи из `domain/capabilities.py`, провайдеры, ссылка «где взять
ключ», бесплатный уровень, заметки, размещение данных в РФ (`rf`), «закрывает ключ модели»
(`model_covers`) и «есть адаптер в коде» (`supported`).

`GET /api/v1/me/tool-catalog` (только cookie-сессия, как и управление ключами):

```json
{
  "checked_on": "2026-11-04",
  "capabilities": [
    {
      "capability": "web_search",
      "label": "Поиск в интернете",
      "description": "Ссылки и выдержки по запросу",
      "tool": "search_web",
      "kinds": ["web_search"],
      "model_coverage": "У Claude — серверный web_search: оплата за поиск, отдельный ключ не нужен",
      "providers": [
        {
          "id": "tavily",
          "label": "Tavily",
          "key_url": "https://app.tavily.com",
          "free_tier": "1000 кредитов/мес без карты",
          "notes": "$0,008 за кредит сверх; поиск для агентов",
          "rf": false,
          "model_covers": false,
          "supported": true
        }
      ]
    }
  ]
}
```

Каталог **дополняет** `GET /me/credentials`, а не дублирует: там «что уже подключено и что
сломалось», здесь — «чем закрыть и где взять ключ». Поддержка в коде (`supported`) берётся из
реестра адаптеров и `USER_PROVIDERS`, поэтому интерфейс не предложит ключ провайдера, которого
ещё нет в коде. Данные сверены по страницам провайдеров 04.11.2026; перед следующей волной их
надо перепроверить — цены и бесплатные уровни меняются.

## Что не сделано

- Вызовы инструментов моделью в агентном цикле (`tools` для `complete_with_tools`) — волна 4;
  сервис и структуры готовы, `WebTools.session(user_id=..., project_id=...)` даёт общий кеш.
- Учёт квоты провайдера в настройках (`остаток`): провайдеры сообщают его по-разному, пока
  проверка ключа только подтверждает доступ; `monthly_limit` ключа маршрутизатор учитывает
  через `exhausted_until`.
- Стоимость вызовов (`cost_usd`): у поиска и чтения нет единой цены за запрос в ответе
  провайдера; оценка прогона их пока не считает.
- Кеш производных источников по хешу и ревизии — вместе с деревом материалов (RFC-0006 шаги 3,
  7).
- Закрытые страницы за логином — только через внешних агентов (RFC-0007).

## Проверки

```bash
cd backend
uv run pytest tests/test_web_adapters.py tests/test_web_tools.py tests/test_tool_catalog.py -q
```

Тесты без сети: `httpx.MockTransport` отвечает записанными ответами провайдеров, ключи — в
in-memory `user_credentials`. Покрыты успех и классы ошибок (429/401/403/413/таймаут), лимиты
размера, дедупликация и кеш, канонический адрес и дата, SSRF-запреты, HTTP-контракт каталога и
приём ключа веб-провайдера в настройках.
