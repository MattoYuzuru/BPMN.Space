# Редактор BPMN (`widgets/diagram-editor`)

Виджет центральной панели рабочего места: bpmn-js Modeler со своей темой, подсветкой вопросов, симуляцией токена, мини-картой, панелью свойств и экспортом. Код — `frontend/src/widgets/diagram-editor/`, демо — `/dev/diagram`.

## Подключение на экране

Импортируйте только из `@/widgets/diagram-editor`. Компонент ленивый: bpmn-js, плагины и их CSS (≈ 470 КБ gzip) приходят отдельным чанком при первом показе редактора.

```tsx
import { useRef, useState } from 'react'
import {
  type DiagramEditorHandle,
  LazyDiagramEditor,
  preloadDiagramEditor,
} from '@/widgets/diagram-editor'

// В loader маршрута рабочего места — чтобы чанк грузился параллельно с данными:
// loader: ({ context }) => { void preloadDiagramEditor(); return … }

function DiagramPanel({ version, question, onSave }: Props) {
  const editor = useRef<DiagramEditorHandle>(null)
  const propertiesRef = useRef<HTMLDivElement>(null)

  return (
    <div className="flex h-full">
      <LazyDiagramEditor
        ref={editor}
        xml={version.xml}
        onChange={onSave} // PUT /projects/{id}/diagram, не чаще раза в 400 мс
        highlights={{
          assumptions: version.assumptionElementIds,
          selected: question?.elementIds ?? [],
          added: version.diff.addedElementIds,
        }}
        onElementClick={(id) => openQuestionsFor(id)}
        onReady={(handle) => handle.setPropertiesPanel(propertiesRef.current)}
        onError={(error) => toast.error(error.message)}
        fallback={<Skeleton className="flex-1" />}
        className="min-w-0 flex-1"
      />
      <div ref={propertiesRef} className="w-80 border-l border-border" />
    </div>
  )
}

// Тулбар экрана: <IconButton onClick={() => editor.current?.fit()} …/>,
// «Показать на схеме»: editor.current?.focusElement(question.elementIds)
```

Высоту задаёт контейнер экрана: корень виджета занимает 100 % родителя.

## Свойства

| Свойство | Что делает |
|---|---|
| `xml` | BPMN 2.0 XML. Новое значение перечитывается в том же редакторе (`importXML`), модель не пересоздаётся. XML, который редактор только что отдал в `onChange`, повторно не импортируется — эхо безопасно. При первом импорте схема вписывается в окно, при следующих сохраняется текущий масштаб и положение. |
| `onChange(xml)` | Схема изменилась (правка, undo, redo, правка в панели свойств). Не чаще раза в 400 мс после последней правки, только при реальном изменении XML (отменённая правка ничего не шлёт), импорт не считается правкой. При размонтировании отложенная правка выдаётся сразу. |
| `onChangePending(pending)` | Синхронно отмечает реальную команду до выдачи XML. Пока сериализация не закончилась, чужая версия не импортируется поверх холста. После выдачи XML, отмены или установки базы — `false`; после ошибки сериализации защита остаётся до отмены/повторной выгрузки. Импорт и режим только просмотра не создают сигнал правки. |
| `readOnly` | Без палитры и контекстного меню, без перетаскивания, правки подписей и горячих клавиш правки; панель свойств становится `inert`. Клики по элементам, масштаб и симуляция работают. |
| `highlights` | `{ assumptions, selected, added }` — массивы id элементов. Можно передавать новый объект на каждый рендер: сравнение по содержимому, маркеры меняются диффом. Неизвестные id пропускаются. |
| `onElementClick(id)` | Клик по элементу (для подписи — id её элемента). Клик по пустому холсту не приходит. |
| `onSimulationChange(state)` | Локальное состояние: `active`, `paused`, `status` (`ready/playing/paused/waiting/completed`), доступные старты, ветви и события. При смене XML режим выключается; тулбар следует этому состоянию. |
| `onSimulationStart()` | Создан экземпляр процесса. Чек-лист `simulation_run` отмечается здесь, а не при простом включении режима. |
| `onReady(handle)` | Первая схема открыта. Удобное место для `setPropertiesPanel`. |
| `onImport({ warnings })` | После каждого успешного импорта; предупреждения bpmn-js (`{ message, elementId? }`). |
| `onError(error)` | `{ kind: 'import' \| 'export', message, warnings, cause }`. `import` — XML не открылся (предыдущая схема остаётся на экране); `export` — не удалось сериализовать изменения для `onChange`. |
| `fallback` | Только у `LazyDiagramEditor`: что показать, пока грузится чанк. По умолчанию — пустой прозрачный блок с тем же `className` (раскладка не прыгает), без спиннера. |
| `className`, `ariaLabel` | Классы корня (`<section>`) и подпись области для скринридера (по умолчанию «Схема процесса»). |

## Императивное API (`ref` или аргумент `onReady`)

| Метод | Поведение |
|---|---|
| `fit()` | Плавно вписать всю схему с отступами 72 px (шире плавающей палитры), не увеличивая больше 100 %. Общий обзор больших схем допускает масштаб ниже 20 %. |
| `zoomIn()` / `zoomOut()` | Шаг ×1,25 вокруг центра окна, обычный масштаб 20–400 %. Из общего обзора ниже 20 % приближение идёт теми же шагами без скачка. |
| `focusElement(id \| id[])` | Плавно центрирует элемент(ы), при мелком масштабе приближает до читаемого, коротко подсвечивает контур. `false`, если id нет на схеме. |
| `exportXml()` | BPMN XML с отступами. |
| `cancelPendingChanges()` | Отменить ещё не выданный XML после явного отказа от локального черновика. Экран сначала скачивает текущую модель через `exportXml()`, затем отменяет отложенную выдачу, debounce сохранения и очередь, после чего загружает серверную версию. |
| `exportSvg()` | SVG в цветах текущей темы: цвета приведены к sRGB-hex (токены в OKLCH внешние редакторы не понимают), шрифт Geist встроен (≈ 60 КБ). |
| `exportPng(scale = 2, { background })` | PNG через canvas. `background: 'surface'` (по умолчанию, цвет `--color-surface`) или `'transparent'`. Масштаб уменьшается сам, если картинка не помещается в canvas браузера. Возвращает `Blob`. |
| `toggleMinimap(open?)` | Показать/скрыть мини-карту (правый верхний угол). Возвращает новое состояние. |
| `toggleSimulation(active?)` | Включить/выключить воспроизведение. Единственный доступный старт запускается сразу; несколько требуют выбора процесса/события в панели. Возвращает состояние режима. |
| `startSimulation(startId?)` | Запустить выбранный старт или продолжить паузу. При нескольких стартах без выбора новый экземпляр не создаётся. |
| `pauseSimulation()` / `resetSimulation()` | Пауза останавливает движение токенов, сброс убирает экземпляры и возвращает выбор старта. |
| `chooseSimulationFlow(flowId)` | Выбрать подписанную исходящую ветвь ожидающего XOR. |
| `triggerSimulationEvent(elementId)` | Явно дать ожидаемое событие (например, таймер/сообщение) и продолжить экземпляр. |
| `setPropertiesPanel(container \| null)` | Отрисовать панель свойств в контейнере экрана или убрать её. Контейнер запоминается и переживает пересоздание редактора. |

Методы экспорта до готовности редактора отклоняются с ошибкой «Редактор схемы ещё не загрузился»; остальные методы тогда ничего не делают. Ошибки экспорта приходят отклонённым промисом (не через `onError`) — экран показывает toast.

Рабочее место сохраняет последний XML действующего холста во время загрузки detail новой версии.
Ожидание запроса после собственного сохранения не заменяет уже открытый bpmn-js скелетоном и не
возвращает XML предыдущей версии: сохраняются текущая модель, direct-editing и стек отмены.

Переключатели мини-карты и воспроизведения ставит экран в свой тулбар. В режиме воспроизведения на холсте есть компактная панель из UI-кита: состояние, пауза/продолжение, сброс, повтор, выбор старта/ветви и продолжение ожидаемого события. Она остаётся внутри изолированного слоя редактора, ниже глобальных диалогов и обучения.

## Воспроизведение и мини-карта

`bpmn/playback.ts` управляет установленным `bpmn-js-token-simulation@1.0.0`. Порядок и семантика остаются у `Simulator`: AND создаёт параллельные токены, join ждёт каждый вход, XOR использует выбранную исходящую стрелку. Перед разветвляющим XOR анимация ставится на паузу и предлагает подписанные ветви; при повторном входе из цикла выбор появляется снова. Завершение определяется по всем работающим scope, а не по первому конечному событию.

Несколько начальных событий обозначают альтернативные запускаемые экземпляры: панель предлагает выбрать один. Таймеры и сообщения запускаются/продолжаются только явным действием пользователя; реальное внешнее событие или истечение бизнес-времени интерфейс не придумывает. Отсутствие поддерживаемого старта и неподдерживаемые элементы показываются как ограничения. Смена версии выключает режим, сбрасывает экземпляры и анимации. ReadOnly сохраняет запрет правок после выключения режима.

Активные узлы и стрелки выделены Током. Токен имеет минимальный размер 12 экранных пикселей на общем плане. При reduced motion движущийся токен скрывается, последовательность показывается статичной подсветкой активного пути. Скорость внизу меняет темп демонстрации; она не описывает duration, рабочие часы или SLA задач. Длительности и переносимые параметры сценариев предложены в [RFC-0003](../rfc/0003-process-playback-and-timing.md) и [ADR-0005](../adr/0005-process-playback.md), задача #17.

`bpmn/runtime-colors.ts` подменяет служебную раскраску библиотеки: цвета живут только в SVG DOM, без записи DI-атрибутов и без `commandStack.changed`/`onChange`. XML сохраняется как обычная BPMN-диаграмма; SVG/PNG дополнительно очищаются от групп токенов, активных маркеров и временных CSS-переменных, сохраняя исходные цвета. Экспорт не останавливает сценарий.

`bpmn/bounded-minimap.ts` оставляет библиотеке рисунок карты, а навигацию ограничивает содержимым с отступом 72 единицы схемы. По оси, где viewport больше схемы, камера центрируется; по меньшей оси остаётся в допустимом диапазоне. Клик плавно центрирует, Ctrl+колесо плавно масштабирует с motion-токенами; drag обновляет камеру по кадрам. Reduced motion переключает вид сразу. Рамка карты всегда внутри её границ; при большом viewport занимает карту, при уходе основного canvas за схему остаётся минимум 2 px на краю. Перемещение элементов и свободный pan основного canvas не ограничиваются. Обработчик viewbox только обновляет карту и не вызывает рекурсивную навигацию.

## Тема

- Цвета элементов читаются из токенов во время выполнения (`getComputedStyle`): заливка — `--color-surface`, линии — `--color-fg-muted`, подписи — `--color-fg`, фон PNG — `--color-surface`, шрифт подписей — `--font-sans` (Geist Variable, 12 px, внешние подписи 11 px). Значения передаются в `bpmnRenderer.defaultFillColor/StrokeColor/LabelColor` и `textRenderer.defaultStyle`.
- Смена темы — `MutationObserver` на `data-theme` (и `class`) у `<html>` плюс `prefers-color-scheme`. Схема перерисовывается в новых цветах без пересоздания модели: история правок сохраняется. Внутри — `ThemedBpmnRenderer`: стандартный BpmnRenderer запоминает цвета в замыкании конструктора, поэтому рисование делегируется его экземпляру, который пересоздаётся с новой палитрой.
- Интерфейс bpmn.io (палитра, контекстное меню, всплывающие меню, подсказки, правка подписей, поиск, мини-карта, панель свойств, симуляция) перекрашен через семантические переменные `@bpmn-io/theme` (`--bio-*` → наши токены) и стили в `ui/styles/`. Сырых цветов в коде нет (design-lint); `!important` — только там, где bpmn-js пишет цвета во встроенный `style`.
- Холст — фон `--color-bg` с сеткой-подложкой из точек (`--grid-line`, шаг `--grid-size`), которая двигается и масштабируется вместе со схемой.
- Анимации — `--ease-soft`, `--duration-*`; при `prefers-reduced-motion` переходы и анимации выключены, `focusElement` и `fit` переключают вид мгновенно.
- Ручное действие прерывает незавершённое движение камеры в текущей позиции: нажатие на элемент,
  начало перетаскивания или редактирования подписи отменяет следующий кадр нашего перехода.
  Иначе `canvas.viewbox.changing` библиотеки мог сразу закрыть подпись, открытую быстрым
  двойным кликом после «Вписать в окно» или изменения масштаба. Переход не доводится скачком до цели.
- Водяной знак bpmn.io (правый нижний угол) не перекрашен, не скрыт и не перекрыт интерфейсом виджета — этого требует лицензия bpmn-js. Не ставьте в правый нижний угол холста свои плавающие элементы.

## Подсветка

Карточка «Элемент схемы» открывается сразу по одиночному клику: показывает источник,
вопросы и допущения элемента. Она выбирает самый удалённый от точки клика угол холста
из верхнего левого, верхнего правого и нижнего левого; нижний правый остаётся знаком
bpmn.io. Карточка не перекрывает повторный клик по выбранной задаче. Двойной клик
закрывает её и начинает обычное редактирование подписи bpmn-js; при перетаскивании
карточка тоже закрывается, а её анимация ухода уже не перехватывает указатель.

| Маркер | Класс | Вид |
|---|---|---|
| `assumptions` | `hl-assumption` | Янтарный пунктир контура (`stroke-dasharray`) и мягкая янтарная подложка; у стрелок — янтарный пунктир. |
| `selected` | `hl-selected` | Контур и подложка «Ток» с мягким свечением. |
| `added` | `hl-added` | Контур и подложка «Хвоя». |
| (focusElement) | `hl-focus` | Контур вспыхивает и гаснет за 1,6 с. |

Классы с префиксом `hl-`, потому что diagram-js сам использует маркеры `selected`, `hover` и т. п. Маркеры появляются и исчезают плавно (переход цвета), во время симуляции не показываются. В экспорт (XML, SVG, PNG) подсветка не попадает.

## Локализация

Сервис `translate` bpmn-js заменён русским словарём (`bpmn/i18n-ru.ts`): палитра, контекстное меню, меню смены типа, выравнивание, поиск, мини-карта, панель свойств для BPMN без расширений Camunda/Zeebe. Симуляция токена переводов не поддерживает — её подсказки и сообщения переводятся обёрткой сервисов журнала и уведомлений и наблюдением за её HTML (`bpmn/simulation-localization.ts`). Новые строки библиотек при обновлении попадут на экран по-английски — добавьте их в словарь.

## Ленивая загрузка и бюджет

- `index.ts` экспортирует только `LazyDiagramEditor`, `preloadDiagramEditor` и типы. Не импортируйте `ui/DiagramEditor` и `bpmn/*` напрямую — bpmn-js окажется в стартовом бандле.
- `make build` после сборки запускает `frontend/scripts/check-bundle.mjs`: стартовые файлы (`index.html` и статические импорты entry) не должны содержать bpmn-js, diagram-js и плагины и должны укладываться в 200 КБ gzip (обоснование — в шапке скрипта). Сейчас ≈ 101 КБ.

## Демо и проверка

`/dev/diagram` (ленивый маршрут) открывает фикстуру `__fixtures__/sample.bpmn` — «Технологическое присоединение (ПП РФ № 861)»: дорожки Заявитель / Сетевая организация / Гарантирующий поставщик, цикл доработки документов, XOR по мощности, AND параллельных мероприятий. Раскладка фикстуры получена `bpmn-auto-layout@2.0.0-alpha.2` при `make fixtures`; рабочий генератор использует граф IR v1 и внутренний Node layout/lint. Кнопок на странице нет:

- в dev-режиме `window.__diagram` — императивное API, `window.__diagramEvents` — журнал событий (`change`, `import`, `error`, `click`);
- подсветка задаётся адресом: `?assumptions=Task_A,Flow_B&selected=Gateway_C&added=Task_D`, `?readOnly=1`; `?broken=1` подсовывает повреждённый XML для проверки `onError`.

Настоящий canvas проверяет `make e2e-diagram`: линейный запуск, пауза/повтор, AND/OR join с ожиданием события, XOR/цикл, событийный шлюз, несколько и одноимённые старты, readOnly, темы/reduced motion, XML/SVG и мини-карта. Отдельный Playwright-конфиг поднимает свой Vite на зарезервированном :5189 с strictPort, без reuse чужого сервера и без backend. Этот gate входит в `make verify`; dev-API `window.__diagramSetXml` меняет фикстуру, `simulation-start` фиксирует реальный запуск.

`generated-graph.spec.ts` дополнительно проверяет девять записанных сценариев IR: XOR,
AND, вложенные ветви, цикл, альтернативные старты, параллельные завершения и три подробных
процесса с 44–49 узлами. Перед
открытием canvas записанный ответ проходит настоящий адаптер, компилятор и временный
HTTP Node layout/lint. Chromium проверяет импорт всех узлов, сохранность семантики
экспорта XML, SVG, видимый запуск токенов, полный общий обзор и реальные SVG-границы
подписей внутри задач. Новые задачи получают серверные размеры под полный текст;
сохранённые ручные размеры автоматически не меняются. Живая модель в этом gate не вызывается.

Логика без настоящего canvas покрыта Vitest: `model/*.test.ts`, `bpmn/translate.test.ts`, `ui/LazyDiagramEditor.test.tsx`, `scripts/check-bundle.test.mjs`.

## Повторная сборка и ручные изменения

Обычная кнопка «Построить схему» сохраняет приоритет ручной логики и геометрию неизменённых
элементов; backend сравнивает граф с generated-базой, а не просит модель переписать XML.
Новые элементы получают раскладку, неподдерживаемая ручная семантика не уплощается.
Точные гарантии и поднабор — [правила генерации](../backend/generation-quality.md).

Меню рядом с кнопкой предлагает «Перестроить из источников». Подтверждение поясняет потерю
ручных изменений в новой версии; прежняя остаётся в истории. `base_version_id` фиксируется
при открытии диалога. При `409` диалог остаётся, данные проекта обновляются; пользователь
может закрыть его и заново подтвердить актуальную версию. Отмена запрос не отправляет.

## Ограничения

- Backend сохраняет ручные правки только в поддержанном поднаборе IR. Произвольный BPMN можно хранить и редактировать, если он прошёл проверки XML; обычная повторная сборка неподдерживаемой семантики отказывает с сохранением текущей версии. Отдельная подтверждённая сборка из источников позволяет создать новый граф без наследования этой логики.
- Повторный импорт сбрасывает историю отмены (поведение bpmn-js): undo не переходит через смену версии.
- Экспорт идёт в цветах текущей темы; в тёмной теме PNG по умолчанию на тёмном фоне `--color-surface`. Для документов экспортируйте в светлой теме или с `background: 'transparent'`.
- Экспорт во время воспроизведения сохраняет обычный рисунок без токенов и служебной подсветки (XML не меняется).
- Встроенный в SVG шрифт — только Geist (латиница и кириллица); при другом `--font-sans` SVG ссылается на шрифт по имени.
- Чанк редактора большой (≈ 470 КБ gzip, из них заметная часть — панель свойств с редактором FEEL); Vite предупреждает о размере чанка. Это ленивая загрузка и на старт не влияет; вызывайте `preloadDiagramEditor()` заранее.
- В тёмной теме водяной знак bpmn.io малоконтрастен (цвет задаёт bpmn-js, менять его нельзя).
