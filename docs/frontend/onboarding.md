# Обучение: движок тура и подсказок

Как устроено обучение новичка: затемнение с «прожектором», карточка с печатью текста, машина шагов и подсказки-указатели. Здесь описан **движок** (`features/onboarding/tour`, `features/onboarding/hint`, компоненты в `shared/ui`), **сценарий** из 11 шагов с приветствием и их подключение к экранам (раздел «Сценарий» ниже). Чек-лист «Начало работы» описан в конце. Визуальные правила — [styleguide.md](styleguide.md) (§5 слои Z, §9 «Обучение», §10 паттерн «Обучение»), живые примеры — раздел «Обучение» на `/styleguide`.
## Принцип

Обучение — надстройка. **Фичи не импортируют `features/onboarding`**: они ставят атрибуты `data-tour` и публикуют сигналы, а тур только слушает. Всё общее лежит в `shared`:

| Что | Где |
|---|---|
| Якоря `data-tour`, константы, `tourAnchor()`, `anchorSelector()`, защита слоёв | `shared/lib/tour-anchors.ts` |
| Шина сигналов приложения | `shared/lib/onboarding-signals.ts` |
| `Spotlight`, `CoachCard`, `Typewriter`, `Beacon` | `shared/ui` |
| `useTypewriter`, `useElementRect` | `shared/hooks` |

Движок грузится отдельным лениво подгружаемым чанком: `TourHost` подключает его, только когда тур активен; без тура нет наблюдателей или кадров измерения геометрии, а публикация сигнала без подписчиков — пустая проверка.

`useElementRect` измеряет активный якорь через `requestAnimationFrame`, сравнивает координаты и обновляет React только при изменении. Это ловит смещение без изменения размера: центрированный диалог переезжает после принятия текстовой подсказки или появления расшифровки. При паузе, завершении, закрытии подсказки и смене якоря прежний цикл снимается. Шаг 4 обводит существующий стабильный блок `voice.capture` со статусом записи, включая «Запись распознана», а не поля названия и расшифровки.

Карточка получает фокус один раз при показе страницы или подтверждения завершения. Если во время шага открыли голосовой поповер, перепорталивание карточки не отбирает фокус у записи. На шаге 7 якорь и опора карточки переходят от формы ответа к `voice.capture` на время диктовки. `Esc` вне карточки принадлежит открытому окну, поповеру или меню независимо от порядка обработчиков; внутри карточки остаётся подтверждением завершения тура.

## Якоря

Целевой элемент помечается `data-tour="…"`; значения — константы `TOUR_ANCHORS` (`projects.new`, `create.submit`, `sources.add`, `run.build`, `share.open` и др.):

```tsx
<Button {...tourAnchor(TOUR_ANCHORS.sourcesAdd)}>Добавить источник</Button>
```

Элемент должен принимать `data-*` (компоненты дизайн-системы отдают его на корневой DOM-узел; если нет — оберните в `span`). Якорь внутри контейнера: `{ name: 'question.answer', within: '[data-question-id="q1"]' }`; произвольный селектор: `{ selector: '…' }`.

## Сигналы

Фичи публикуют факты **после успеха на сервере**:

```ts
emitOnboardingSignal({ type: 'source.added', kind: 'text' })
```

| Сигнал | Данные |
|---|---|
| `project.created` | `id` |
| `source.added` | `kind` |
| `voice.permission-denied`, `voice.unavailable` | нет |
| `run.started` | `id` |
| `run.status` | `status`: `queued` / `running` |
| `run.finished` | `status`, `openQuestions`, `hasDiagram` |
| `run.presented` | `runId`, `projectId`: итог прочитан или закрыт пользователем |
| `question.answered`, `question.ignored` | `id` |
| `share.created` | нет |
| `dialog.opened` | `name` |

Подписка — `subscribeOnboardingSignals(listener)` (возвращает отписку).

## Шаг тура

Шаг — данные (`TourStep<Ctx>`, `features/onboarding/tour/types.ts`):

| Поле | Что |
|---|---|
| `key`, `chapter`, `title` | ключ шага (совпадает с бэкендом), ключ главы (подпись — в `chapters` у `TourHost`), заголовок карточки |
| `kind` | `story` рассказ («Назад»/«Далее»), `action` действие («Пропустить шаг»), `wait` ожидание, `finish` финал по центру |
| `pages` | 1–3 страницы: `{ text, title?, anchor?, side?, allowOutside? }`; страница перекрывает якорь шага |
| `anchor`, `side` | якорь (значение, `{name, within}`, `{selector}` или функция от контекста); нет — по центру |
| `route(ctx)` | экран шага `{ to, params?, search?, alt? }`: движок сам переходит туда, а если пользователь ушёл — ставит тур на паузу |
| `until(signal, ctx)` | сигнал, завершающий `action`/`wait` |
| `doneWhen(ctx)` | то же по состоянию приложения (проверяется после каждого обновления контекста) |
| `skipIf(ctx)` | шаг пропускается — при входе и пока идёт (ветвления); не должен давать `true`, пока данные грузятся |
| `optional` | якорь не найден за таймаут — шаг молча пропускается |
| `prepare(ctx)` | подготовить экран при входе (развернуть панель через публичный стор фичи); может вернуть функцию очистки |
| `allowOutside` | клики вне выреза разрешены |
| `actions` | кнопки справа вместо стандартных: `{ id, label, variant?, tone?, run(api) }`; `api` — `next`, `back`, `skipStep`, `goto(key)`, `finish(reason)` |
| `view(v)` | динамический вид: `{ title?, pages?, tone?, actions?, anchor?, side?, allowOutside? }`; `v` — `ctx`, `elapsedMs`, `seen` (сигналы шага), `page` |
| `ticks` | моменты (мс от входа), в которые пересчитать `view` (таймауты 60 и 150 с) |

Правила машины: «Назад» показывается только у рассказов (на первой странице — если предыдущий шаг тоже рассказ); «Далее» на последней странице идёт к следующему непропущенному шагу, после последнего тур завершается как `completed`; `goto(key)` нужен для ветвлений («Повторить», «Пропустить главу»); завершение — крестик или `Esc` и подтверждение внутри карточки (`dismissed`).

Ожидание якоря: `MutationObserver` плюс опрос раз в 250 мс до `anchorTimeoutMs` (по умолчанию 5 с). Пока ждём — затемнение держится, карточки нет. Не нашли: карточка по центру без выреза; у шага-действия ожидание сигнала продолжается.

## Подключение

```tsx
<TourHost
  enabled={onboarding.tour.status === 'active'}   // сервер говорит «тур идёт»: восстановить шаг
  steps={steps}
  context={ctx}                                    // id проекта, вопросы, прогон…
  persistence={persistence}
  chapters={{ sources: 'Источники', questions: 'Вопросы', diagram: 'Схема' }}
  onEnd={(reason) => …}                            // 'completed' | 'dismissed'
/>
```

`startTour(stepKey)` запускает тур с шага, `stopTour()` останавливает без записи на сервер.

**`TourPersistence`** — интерфейс хранения, движок не знает про API:

```ts
interface TourPersistence {
  load(): Promise<{ status: 'pending' | 'active' | 'completed' | 'dismissed'; step: string | null }>
  saveStep(step: string): Promise<unknown> | undefined   // вход в шаг
  setStatus(status: 'active' | 'completed' | 'dismissed'): Promise<unknown> | undefined
}
```

Вызовы идут в фоне, без ожидания ответа, с одним повтором через 1,5 с при ошибке. При монтировании (`restore`, по умолчанию включено) движок берёт `load()` и, если тур активен, продолжает с сохранённого шага (его повторно не пишет). Отдельной логики для нескольких вкладок нет: побеждает последнее изменение.

## Слои и модальные окна

Шаги, подсвечивающие элемент внутри `Dialog` или `Sheet`, ломают наивную схему: модальный слой делает `body` некликабельным, держит фокус и закрывается по клику снаружи и по `Esc`. Поэтому:

- затемнение тура не рисуется (у окна своё), остаётся кольцо у элемента;
- карточка рендерится внутрь узла окна (портал с `container`), то есть внутри `FocusScope`; её показ ждёт окончания анимации окна;
- `DialogContent`, `SheetContent`, `DropdownMenuContent` и `PopoverContent` игнорируют `onInteractOutside` и `onEscapeKeyDown`, если событие внутри `[data-tour-layer]` (`guardTourLayer`); для касаний слой запоминает, где началось нажатие;
- меню `DropdownMenu` тур не открывает и не контролирует; пока меню или список выбора открыты, затемнение и перехват кликов снимаются (меню лежит на `z-50` под затемнением `z-60`).

## Подсказка-указатель

`showHint({ anchor, text, prepare? })` из `features/onboarding/hint`: пульсирующее кольцо и поповер с «Понятно», без затемнения; одна подсказка за раз. `prepare` готовит экран; якорь не найден за 5 с — `toast` с тем же текстом. Хост — `<HintHost />` (грузит чанк, только когда есть подсказка).

## Как добавить шаг

1. Поставьте `data-tour` на целевой элемент (константа в `TOUR_ANCHORS`) и, если нужно, опубликуйте сигнал после успеха на сервере.
2. Опишите шаг в сценарии: `kind`, `anchor`, `pages` (до 160 символов, на «вы», без восклицаний), `until`/`doneWhen` для действий, `skipIf` для ветвлений.
3. Покажите его на `/styleguide` → «Обучение», если это новый вид шага.
4. Тесты — рядом с кодом (`machine.test.ts`, `tour-host.test.tsx`).

### Сигналы

Публикуются **после ответа сервера**: `source.added` (текст, голос, файл, пример — `entities/source`), `question.answered` и `question.ignored` (`entities/question`: не по оптимистичному обновлению), `share.created` (`entities/share`), `project.created` (диалог создания проекта), `voice.permission-denied` и `voice.unavailable` (запись голоса), `run.started`, `run.status` (`queued` или `running`), `run.finished` (`status`, число открытых вопросов, есть ли схема) — `features/run-analysis/use-run-tracker.ts`. Если поток событий прогона потерян, трекер раз в 5 с опрашивает `GET /runs/{id}` и после финального статуса публикует `run.finished`.

`session.ts` подписывается на сигналы при загрузке модуля — раньше хоста тура, поэтому к моменту, когда хост решает, какой шаг показать дальше, итог прогона и учебный проект уже записаны (поля `TourContext`, которые меняются сигналами, — геттеры над сессией).

Положение карточки: `side`, `align` (`start` / `center` / `end`) и `cardAnchor` — опора карточки отдельно от выреза (шаги 7–8: карточка у всей карточки вопроса, подсвечена кнопка внутри). Все три можно задать у шага, страницы и в `view`.

Окна (меню, диалоги) состоянием тура не управляются: какой якорь сейчас на экране, шаги узнают по DOM (`use-anchor-presence.ts`, опрос раз в 250 мс только пока идёт шаг с окном).

### Ветвления

`run.finished` обновляет данные и чек-лист немедленно. При успешном активном прогоне шаг `run.wait` ждёт также завершения показа: карточка прогресса заканчивает подтверждённые этапы и оставляет итог на 2,5 с, затем публикует `run.presented`. Ошибка/отмена обходят эту паузу. Исторический результат или закрытая пользователем карточка не заставляют повторять очередь; сигналы другого проекта не переводят учебный шаг.

- **Итог прогона** (`run.finished`): `succeeded` — шаги 7–8 по числу вопросов, затем 9–11; `failed` и вопросы есть — шаги 7–8, шаг 9 пропущен; `failed` и вопросов нет — карточка «Модель не ответила. Попробуем ещё раз?» с «Повторить» (новый прогон, шаг 6 заново) и «Пропустить главу» (к шагу 10); `succeeded` без вопросов — карточка «Модель всё поняла сама…» и «Далее» (к шагу 9). Вопрос один — шаг 8 пропускается.
- **Долгий прогон**: страница шага 6 зависит от этапа; «в очереди» — после 3 с; через 60 с «Модель думает дольше обычного»; через 150 с к кнопкам добавляется «Пропустить главу» (прогон продолжается в фоне).
- **Перезагрузка**: тур продолжается с начала текущего шага по состоянию сервера. После перезагрузки на шагах после прогона итог берётся из данных учебного проекта (`TourRoot`).
- **Учебный проект удалён** (404 при запросе проекта): любой шаг показывает «Начать заново» (`POST /me/onboarding/tour/restart`, затем шаг 1) или «Завершить».
- **Микрофон**: отказ или отсутствие — текст про готовую голосовую заметку в «Примерах» и «Пропустить шаг».
- **Свёрнутые панели**: `prepare` шагов просит `expandPanel`; `WorkspaceView` исполняет просьбу сам.
- **Esc**: привязанная карточка — не слой Radix (части `Popper` без `DismissableLayer`), поэтому открытое окно остаётся верхним слоем и `Esc` закрывает его. Без окна `Esc` (как и `Esc` внутри карточки) открывает в ней подтверждение завершения.
- **Перезагрузка на шагах с окном (3, 4, 10)**: окно заново не открывается — шаг начинается с кнопки меню или «Поделиться». Отклонение от эпика осознанное: диалог источника или ссылки (адрес показывается один раз) заново «открыть» нечем без вмешательства в состояние фичи.
- **Конкурентные сигналы**: все `run.*` несут `projectId`, сессия тура игнорирует прогоны других проектов (пока тур на паузе пользователь мог запустить прогон в другом). `run.started` публикует только реальный запуск (`useStartRun`), не повторное подключение трекера к идущему прогону; «Повторить» ставит в сессии `retryPending`, пока новый прогон не стартовал. Если прогон закончился, пока никто не слушал, итог берётся из данных проекта.

### Как добавить шаг сценария

1. Поставьте `data-tour` на элемент (константа в `TOUR_ANCHORS`), при необходимости опубликуйте сигнал после ответа сервера.
2. Добавьте ключ в `STEP_KEYS` (он обязан совпасть с `TourStepKey` бэкенда) и шаг в `baseSteps` в `steps.ts`; тексты — в `copy.ts`.
3. Всё, что шагу нужно знать про экран, — через `TourContext`; если нужен новый рычаг, добавьте его в `TourUi` и подставьте в `TourRoot` из публичной точки расширения фичи (фичи не импортируют тур).
4. Проверьте шаг в `steps.test.ts` и ветвления в `e2e/onboarding-tour.spec.ts`.

### e2e тура

Сценарии тура — отдельный проект Playwright `onboarding` (`playwright.config.ts`): он зависит от проекта `e2e` (`dependencies`) и стартует после него, чтобы прогоны mock-модели и регистрации (лимит 20 в минуту на адрес) не мешали остальным. Следствие: если проект `e2e` упал, тур-тесты не запускаются («did not run») — смотрите на падение `e2e`. Чек-лист «Начало работы» (`checklist.spec.ts`) — проект `checklist`, зависит от `onboarding` (оба регистрируют пользователей и делят лимит запросов). Отдельно: `npm run --workspace frontend e2e -- --project=onboarding` (без зависимостей: `--no-deps`).

## Чек-лист «Начало работы»

12 пунктов в 4 группах; источник правды — бэкенд ([../backend/onboarding.md](../backend/onboarding.md)), на фронтенде — метаданные пунктов (`entities/onboarding/items.ts`) и показ. Паттерн и состояния — [styleguide.md](styleguide.md) §10, раздел «Начало работы» на `/styleguide`.

| Что | Где |
|---|---|
| Данные, мутации, `fetchItemTarget`, `useChecklistView` (прогресс для меню, плашки, панели) | `entities/onboarding` |
| Открыть панель из любого места: `useOnboardingUi().openChecklist()` | `entities/onboarding/ui.ts` (нейтральный стор: меню аккаунта, плашка, уведомление и тур не импортируют друг друга) |
| Пункт меню аккаунта | `features/account-menu` |
| Панель, переход к пункту, уведомления, слой в `_app` | `widgets/onboarding-checklist` |
| Плашка | `widgets/onboarding-pill` |

### Свежесть данных

Состояние перечитывается (`invalidateQueries(['onboarding'])`) после **любой** успешной мутации (подписка на `MutationCache` в `OnboardingWatcher`, без фильтра по ключу: его у мутаций нет, а загрузка файла — тоже мутация, пусть и через XHR; мутации с `meta.skipOnboarding` — выход и отметки клиента — пропускаются), после прогона (сигнал `run.finished` и конец прогона в `useRunTracker`). Кнопок «Обновить» нет.

### Клиентские пункты

`simulation_run` — после создания реального экземпляра процесса (`DiagramPanel.onSimulationStart`), а не при включении режима; при нескольких стартах сначала нужен выбор. `diagram_exported` — когда файл отдан браузеру (`exportDiagram({ onSaved })`, оба меню скачивания). Отправляет `useReportOnboardingEvent`: если пункт уже отмечен в кэше — запрос не уходит, ответ не ждём.

### Переход к пункту

`useVisitItem().visit(item)`:

1. `GET /me/onboarding/items/{item}/target` → `{route, project_id?, question_id?, hint}`;
2. панель закрывается, переход на экран проектов или в рабочее место (`?question=<id>`, если сервер назвал вопрос);
3. `planItemVisit` (`target.ts`) выбирает якорь по `item` и `hint` (`TOUR_ANCHORS`; для вопросов — внутри `[data-question-id]`) и текст подсказки; `showHint` показывает указатель. Вопрос и его вкладку выбирает `?question=`. Перед показом `prepare` просит стор рабочего места: `useWorkspaceUi.expandPanel('sources' | 'questions')` и `focusQuestion(id)` (показать вопрос на схеме); исполняет `WorkspaceView`.

Подсказка закрывается сама, когда пункт стал выполненным (`OnboardingWatcher`). Не нашли якорь за 5 с — тот же текст уведомлением (это делает `HintHost`).

### Уведомления

`OnboardingWatcher` (в `OnboardingLayer`, подключённом в `routes/_app.tsx`) — единственное место, где сравниваются ответы `GET /me/onboarding`. Первый ответ не объявляется; во время тура (и в тот же ответ, в котором он закончился) — тишина; один новый пункт — «Готово: …», несколько — «Готово: N шагов», последний — «Вы освоили Архитектор». Недавние пункты (5 с) запоминаются для анимации в панели.

### Как добавить пункт

1. Ключ приходит из контракта API (`ChecklistItem`); без записи в `META`/`ORDER` в `items.ts` проект не соберётся.
2. Якорь действия — в `DO_ANCHOR`, текст — в `DO_TEXT` (`widgets/onboarding-checklist/target.ts`); если действия может не быть на экране — раскрытие панели в `planItemVisit`.
3. Тест в `target.test.ts` проверит оба сопоставления для всех пунктов.
