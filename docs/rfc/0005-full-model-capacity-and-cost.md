# RFC-0005. Полная мощность модели: возможности, профиль запуска и стоимость

- Дата: 2026-11-04
- Статус: реализованы шаги 1–5 (справочник возможностей, бюджет контекста и `max_tokens` из
  модели, профиль `effort` + `semantic_review` в API и интерфейсе, раздельный учёт кеш-токенов,
  стоимость прогона и оценка до запуска, бюджет в деньгах с мягкой остановкой вместе с
  техническими вопросами RFC-0006). Поле профиля `mode` (`pipeline`/`agent`) реализовано вместе
  с агентным режимом [RFC-0004](0004-agent-mode.md), бюджет ходов — там же; шаг 6 (подъём
  пределов IR) — предложен
- Связано: [RFC-0001](0001-architecture.md) §5, [RFC-0004](0004-agent-mode.md),
  [RFC-0006](0006-tools-connectors-and-derived-sources.md),
  [ADR-0011](../adr/0011-user-llm-credentials.md), [ADR-0012](../adr/0012-long-documents-and-media.md),
  [generation-quality.md](../backend/generation-quality.md)

## Зачем

Главный сценарий — аналитик или аудитор загружает многочасовые записи совещаний, регламенты и
выгрузки и хочет одну подробную схему. Качество первой генерации решает всё. Сейчас его
ограничивают не модели, а наши постоянные пределы:

| Предел | Сейчас | Что даёт модель (Claude 5.5) | Следствие |
|---|---|---|---|
| `LLM_CONTEXT_BUDGET_CHARS` | 120 000 знаков (≈ 40–50 тыс. токенов) для любой модели | окно 1 млн токенов | проект, который целиком помещается в окно, всё равно режется на порции и сжимается в выдержки |
| `LLM_JSON_MAX_TOKENS` | 16 384 | до 128 тыс. токенов ответа (потоком) | подробный граф или длинный список вопросов обрывается по `max_tokens` |
| `LLM_ANTHROPIC_EFFORT` | один на сервер, из `.env` | `low` … `max` на каждый запрос | пользователь не может попросить «тщательно» |
| IR v1 | 30 дорожек, 100 узлов, 200 потоков | — | подробный процесс крупного подразделения не помещается |
| Оценка стоимости | нет | `count_tokens`, цены моделей | пользователь не знает, во что обойдётся «максимум» |

Цель RFC: **пределы качества выводятся из возможностей выбранной модели и выбора пользователя,
а не задаются числом в `.env`.** Защитные пределы остаются.

## Два вида пределов

**Защитные** — оберегают сервер и данные, не снимаются: защита от zip-бомб, SSRF и закрепление
IP (ADR-0011), `LLM_MAX_RESPONSE_BYTES`, лимиты частоты запросов, размер загрузки на диск
(`MAX_UPLOAD_BYTES`, `MAX_MEDIA_BYTES` — слабая VPS), таймаут разбора одного документа.

**Потолки качества** — заменяются расчётом:

| Параметр | Станет |
|---|---|
| `LLM_CONTEXT_BUDGET_CHARS` | `окно модели × знаков на токен × запас` из справочника возможностей; переменная остаётся только для неизвестных моделей |
| `LLM_JSON_MAX_TOKENS` | максимум ответа модели; запросы больше ~16 тыс. токенов идут потоком (адаптер Anthropic это уже требует) |
| `LLM_CHUNK_CHARS` | применяется, только если источники не помещаются в бюджет; иначе весь проект идёт одним кешируемым префиксом |
| `RUN_DEADLINE_MAX_SEC` | следует из бюджета запуска (токены, деньги); абсолютный срок остаётся как страховка, но настраивается пользователем |
| `MAX_TEXT_CHARS`, `MAX_PDF_PAGES` | остаются защитными для разбора на сервере; PDF, который модель читает сама (RFC-0006), ими не ограничивается |
| Пределы IR | поднимаются после замера `infra/bpmn-tools` на 300–500 узлах; подпроцессы и пулы — отдельное расширение IR |

Коэффициент «знаков на токен» для русского текста заметно ниже, чем для английского. Его не
угадываем: берём из `count_tokens` на эталонах (`prompt-eval`) и храним в справочнике по
семейству токенизатора.

## Справочник возможностей моделей

`ModelCapabilities` — данные, а не код в промптах:

| Поле | Откуда |
|---|---|
| `context_tokens`, `max_output_tokens` | Models API провайдера (у Anthropic — `max_input_tokens`, `max_tokens`) |
| `vision`, `pdf_input`, `tools`, `server_tools` | Models API (`capabilities`) + статический каталог |
| `effort_levels`, `effort_default` | каталог: у Opus 5.5 и Haiku 5.5 по умолчанию `medium`, у Sonnet 5.5 — `high` |
| `accepts_temperature` | каталог: Anthropic отклоняет `temperature/top_p/top_k` на всех моделях (API от 2026-10-21), рассуждающие модели OpenAI тоже |
| `price_in`, `price_out`, `price_cache_read`, `price_cache_write` | каталог с датой; для совместимых провайдеров пользователь вводит цены сам |
| `chars_per_token` | замер на эталонах |
| `tier_hint` | роль в оркестрации: `orchestrator`, `worker`, `cheap` |

Каталог лежит в коде с датой проверки, Models API уточняет его при подключении ключа
(кеш `LLM_MODELS_CACHE_SEC`). У неизвестной модели совместимого провайдера — осторожные
значения по умолчанию и правка в настройках («окно контекста этой модели»).

Справочник отвечает и на вопрос «чтобы Opus не запускал десять дорогих помощников». Модель не
обязана знать свои сильные стороны: оркестратор получает в системном промпте таблицу доступных
моделей с ролями и ценами, а сервер ограничивает число помощников и бюджет.

## Профиль запуска

Профиль — набор настроек одного прогона. Хранится как умолчание пользователя в настройках, и
его можно переопределить при запуске.

| Поле | Значения | Заметки |
|---|---|---|
| `credential_id`, `model` | как сейчас (ADR-0011) | |
| `effort` | `low`, `medium`, `high`, `xhigh`, `max` | Anthropic — `output_config.effort`; OpenAI — `reasoning_effort` (ближайший уровень); DeepSeek — `thinking` вкл/выкл; модель без рассуждения — поле скрыто |
| `mode` | `pipeline`, `agent` | `agent` — RFC-0004, только для моделей с инструментами |
| `worker` | `credential_id` + `model` или пусто | дешёвая модель для чтения порций, описания кадров, черновых выдержек |
| `budget` | лимит токенов и/или денег | при достижении прогон завершается корректно и задаёт технический вопрос (RFC-0006) |
| `semantic_review` | вкл/выкл | сейчас глобальный `LLM_SEMANTIC_REVIEW` |
| `parallel_requests` | 1…32 | умолчание из провайдера; у Anthropic упирается в лимиты организации |
| `temperature` | число | показывается только при `accepts_temperature`; для JSON по умолчанию 0 |

**Температура не главная ручка.** У моделей Claude и рассуждающих моделей OpenAI её нельзя
задать, у остальных для структурного JSON полезен только 0 (так уже настроено для DeepSeek).
Качество меняют effort, модель, режим и бюджет. Температура остаётся в «Дополнительно» для
провайдеров, которые её принимают.

`ir.execution` прогона дополняется профилем (без ключей), чтобы восстановление после рестарта
(ADR-0008) продолжало тот же запуск.

## Оценка стоимости

**До запуска** — `POST /projects/{id}/runs/estimate` с профилем:

1. Токены входа: Anthropic — `messages/count_tokens` (бесплатно); остальные — знаки ÷ `chars_per_token`.
2. План вызовов: для конвейера число запросов известно (порции × этапы, смысловая сверка,
   исправления); для агента — диапазон от «прочитал оглавление» до «исчерпал бюджет».
3. Цены из справочника, чтение кеша — по цене кеша (у Claude ≈ 0,1 цены входа, запись ≈ 1,25).
4. Расход инструментов из RFC-0006: минуты распознавания, кадры, поиски.

Ответ — диапазон, а не одно число: `{tokens: {min, max}, cost: {min, max, currency}, duration,
breakdown[]}`. Если на пути есть модель без цен, сумма помечается «неполная».

**Во время и после** — по `llm_calls`. В таблицу добавляются `cache_read_tokens`,
`cache_write_tokens` и `cost` по ценам на момент вызова. Интерфейс показывает «потрачено $2,71
из $10». У прогона — итог и разбивка по этапам.

Для неспешных повторных прогонов позже можно добавить Batch API Anthropic (скидка 50%, результат
не сразу). В первую очередь это не входит.

## Интерфейс

- Кнопка «Анализ» получает меню профиля: «Быстро / Обычно / Тщательно / Максимум», под ним
  модель, режим и оценка «≈ $1,8–3,2 · ~6 мин». Пресеты — это наборы `effort` + `mode` +
  `semantic_review`, а не отдельная логика.
- Шапка проекта: модель, уровень и бюджет одной меткой «Opus 5.5 · тщательно · ≤ $10».
- Настройки → «Модели и ключи»: возможности модели (окно, vision, инструменты, цены с датой),
  профиль по умолчанию, модель для черновой работы, раздел «Дополнительно».
- Прогресс прогона: текущая стоимость и бюджет.

## Как внедрять

1. Справочник возможностей и бюджет контекста из модели. Это исправляет главное ограничение;
   эталоны `prompt-eval` сравнивают «весь проект в окне» и «порции».
2. `max_tokens` из модели, потоковые ответы для больших значений.
3. Профиль запуска в API (`RunCreate.profile`) и в интерфейсе, effort на запрос.
4. Оценка стоимости и учёт кеш-токенов в `llm_calls`.
5. Бюджет в деньгах с корректной остановкой (вместе с техническими вопросами RFC-0006).
6. Замер layout и подъём пределов IR.

## Что реализовано (шаги 1–5)

- `backend/app/llm/capabilities.py` — справочник: каталог Claude 5.5/5 с ценами на 2026-10-06,
  уточнение из Models API Anthropic, осторожные умолчания для OpenAI, DeepSeek и прочих.
- Бюджет источников и `max_tokens` считаются в `llm/factory.py` при выборе модели; формула и
  таблица — [generation-quality.md](../backend/generation-quality.md#пределы-из-возможностей-модели-rfc-0005-шаги-13).
  `chars_per_token` = 2,0 для русского — заведомо низкая оценка до замера `count_tokens`;
  ответ «вход длиннее окна» переводит прогон на порции.
- `RunCreate.profile` (`effort`, `semantic_review`) с проверкой по модели (422), хранение в
  `ir.execution.profile` и восстановление после рестарта; `GET /me/llm-credentials/{id}/models`
  отдаёт возможности моделей.
- Интерфейс: уровень в `ModelPicker` и в метке шапки, возможности модели под выбором модели ключа.
- **Учёт кеш-токенов и стоимость** (шаг 4). `LlmUsage` (`llm/base.py`) разделяет обычный вход,
  чтение (`cache_read_tokens`) и запись (`cache_write_tokens`) кеша; Anthropic сообщает
  `cache_read_input_tokens`/`cache_creation_input_tokens`, OpenAI и совместимые —
  `prompt_tokens_details.cached_tokens` и `prompt_cache_hit_tokens`. В `llm_calls` добавлены
  `cache_read_tokens`, `cache_write_tokens`, `cost_usd`, `price_checked_on` (миграция
  `0018_llm_call_cost`); цена — из справочника на момент вызова, у совместимого провайдера без
  цен стоимость остаётся `null`. `GET /runs/{id}` и SSE-событие `usage` отдают потраченное с
  разбивкой по этапам (`RunCost`, `by_stage`); `done` содержит итог.
- **Оценка до запуска**: `POST /projects/{id}/runs/estimate` (`RunEstimate`) — диапазоны
  `tokens`, `cost`, `duration`, `breakdown` по этапам и `complete=false`, если цены модели
  неизвестны. План вызовов рассчитывает чистый `llm/estimate.py` по текущим правилам конвейера:
  проект целиком в бюджете — один запрос на этап и до трёх исправлений, иначе порции,
  извлечение оснований и смысловая сверка. `count_tokens` добавлен в порт `LlmClient`: у Anthropic
  это бесплатный `messages.count_tokens` (и калибровка знаков на токен), у остальных — знаки ÷
  `chars_per_token`. `services/estimate.py` собирает материалы, профиль и модель.
- **Режим прогона** (RFC-0004). `RunProfile.mode` — `pipeline` (фиксированный конвейер) или
  `agent` (модель сама читает источники инструментами); `RunProfile.max_steps` ограничивает
  агентные ходы и допустим только с `mode=agent`. Проверка в `services/model_resolver.py`:
  `agent` требует включённого оператором `LLM_AGENT_MODE` и модели с инструментами
  (`capabilities.tools`); иначе 422. Профиль с режимом сохраняется в `ir.execution.profile` и
  восстанавливается после рестарта. Оценка `POST /projects/{id}/runs/estimate` для агента даёт
  диапазон ходов от «оглавление и submit» до лимита и честно помечает его приблизительным:
  путь чтения выбирает модель.
- **Бюджет и мягкая остановка** (шаг 5). `RunProfile.budget {tokens?, cost_usd?}` хранится в
  `ir.execution.profile` вместе с профилем и проверяется в `llm/pipeline.py` перед каждым
  запросом к модели по накопителю всего прогона (`llm/base.py:track_run_usage`; после
  продолжения после `waiting` в счёт входит и потраченное раньше по журналу `llm_calls`).
  Достигнутый бюджет — не ошибка: прогон переходит в `waiting`, создаётся блокирующий
  технический вопрос `budget_reached` с действиями «поднять бюджет» и «открыть настройки»
  (RFC-0006, шаг 2). Действие «поднять бюджет» объединяет старый и новый бюджет монотонно
  вверх (задание стоимости не теряет лимит токенов), проверяет известность цен модели и
  требует границу выше уже потраченного — иначе 422. `POST /runs/{id}/resume` без поднятия
  исчерпанного бюджета возвращает 409, а не новый вопрос после одного запроса; после
  продолжения потраченное до `waiting` входит в счёт. Бюджет в деньгах требует известных цен
  модели: иначе 422, а не молчаливое обещание остановки; на mock-модели бюджет отклоняется.

Ещё не сделано: шаг 6 (замер layout и подъём пределов IR), `worker`,
`parallel_requests`, `temperature` в профиле, переход на порции при 429 по лимиту входных
токенов в минуту (пока есть только потолок оператора `LLM_CONTEXT_BUDGET_MAX_CHARS`),
потоковые ответы OpenAI-совместимых серверов, профиль по умолчанию в настройках пользователя
(сейчас уровень запоминается вместе с выбором модели на устройстве), возможности модели сервера
в интерфейсе.

## Риски

- **Лимиты организации провайдера.** Запрос на 600–900 тыс. токенов может превысить лимит
  входных токенов в минуту для аккаунта начального уровня. На 429 с таким признаком прогон
  переходит на порции, а не падает.
- **Качество на очень длинном контексте.** Модель с полным проектом может пропустить деталь в
  середине. Проверка дословных цитат остаётся, а выбор «окно или порции» решают эталоны, а не
  вера в размер окна.
- **Стоимость.** «Максимум» на часе видео может стоить десятки долларов. Оценка до запуска,
  бюджет и остановка с вопросом — обязательная часть, а не украшение.
- **Устаревшие цены.** Каталог датирован, совместимые провайдеры правятся пользователем, а
  оценка помечается как приблизительная.

## Не входит

Учёт стоимости по команде и общие ключи команды (ADR-0011), биллинг продукта, Batch API.
