## Зачем

Материал аналитика — это не только текст. Это часовые записи, демо интерфейса на видео, сканы
регламентов, ссылки на сайты, где идёт процесс. Сейчас сервер умеет одно: превратить звук в
текст с метками `[мм:сс]` через Deepgram (ADR-0012). Картинка видео теряется, сканы PDF
пропускаются с предупреждением, внешние страницы не читаются.

Ограничения продукта:

- **Без локальных моделей.** VPS слабая: распознавание, OCR и понимание видео выполняют внешние
  API по ключам пользователя. На сервере остаются только лёгкие операции (ffmpeg, ffprobe,
  разбор OOXML/PDF).
- **Независимость от провайдера.** Модель просит «расшифруй запись», а не «вызови Deepgram».
  Какая реализация ответила, ей не важно.
- **Ничего тихо не теряется.** Нехватка квоты, ошибка ключа или неполная обработка видны модели
  и пользователю.

## Возможности вместо провайдеров

Возможность (capability) — тип задачи с единым контрактом входа и выхода. Пользователь
подключает к ней один или несколько ключей; сервер выбирает реализацию.

| Возможность | Инструмент для модели | Результат | Уже покрывает ключ LLM |
|---|---|---|---|
| `speech_to_text` | `transcribe(media_id, range?)` | реплики с таймкодами, говорящими, языком | у OpenAI — да (transcribe); у Claude — нет: аудио на вход не принимается |
| `vision` | `describe_images(image_ids[], question)` | описание, текст на экране, элементы интерфейса | Claude, GPT, Gemini — да |
| `ocr` | `ocr_pages(source_id, pages[])` | текст страниц с разметкой | Claude читает PDF сам (до 600 страниц и 32 МБ на запрос), отдельный OCR-провайдер дешевле на больших сканах |
| `video_understanding` | `analyze_video(media_id, question, range?)` | события с таймкодами | Gemini принимает видео целиком; Claude — только через кадры |
| `web_search` | `search_web(query, recency?)` | ссылки, выдержки, дата | у Claude — серверный `web_search` (оплата за поиск) |
| `web_fetch` | `read_url(url)` | текст страницы, дата получения | у Claude — серверный `web_fetch`, только для адресов, уже появившихся в разговоре |
| `code_execution` | `run_code(script, files[])` | stdout, файлы | у Claude — серверная песочница; на нашей VPS код не выполняется |
| `text_to_speech` | `speak(text, voice?)` | аудиофайл | нет; низкий приоритет (озвучка вопросов для интервью, аудиорезюме) |

Если ключа под возможность нет, но её покрывает модель (vision, PDF, поиск у Claude), используется
модель. Если нет ни того, ни другого, инструмент не показывается модели. Промпт не обещает того,
чего нет.

**Статус:** `llm` работает по ADR-0011; `speech_to_text` переведён на ключи пользователя и
маршрутизатор (шаг 1). Для `vision`, `ocr`, `video_understanding`, `web_search`, `web_fetch`,
`tts` в `backend/app/ingest/adapters/` лежат контракты адаптеров и типы запросов/ответов, вызовы
ещё не реализованы — это волна 3.

Закрытые системы (Confluence, внутренние порталы, страницы за логином) сервер не читает: у него
нет доступа к сети и сессии пользователя. Это закрывают внешние агенты пользователя через MCP
([RFC-0007](0007-external-agents-mcp.md)). Встроенный браузер с логином пользователя в продукте
не планируется.

## Ключи

`user_llm_credentials` обобщается до `user_credentials`: `kind` (`llm`, `speech_to_text`,
`ocr`, `vision`, `video`, `web_search`, `web_fetch`, `tts`), `provider`, `label`, шифртекст
(Fernet, как в ADR-0011), `priority`, `enabled`, `monthly_limit` (необязательно: минуты,
запросы, деньги), `exhausted_until`, `last_error_code`. Один ключ может закрывать несколько
возможностей (ключ OpenAI — LLM, распознавание, vision); тогда это одна строка с несколькими `kind`.
Правила SSRF, закрепление IP и запрет возврата ключа из ADR-0011 распространяются на все
адаптеры.

**Реализовано:** таблица `user_credentials` (миграция `0020_user_credentials`), REST
`/me/credentials` (+ `POST /{id}/check`, карточки возможностей в списке) и совместимый
`/me/llm-credentials`; ключи перебираются по приоритету, выключенные и исчерпанные пропускаются.
Каталог провайдеров в коде не хранится: «Где взять ключ» — данные интерфейса из
[каталога](../research/tool-providers-2026-11.md).

Настройки → «Инструменты»: карточка на возможность, в ней ключи по приоритету, кнопка
«Проверить», остаток квоты, если провайдер его сообщает, и ссылка «Где взять ключ» из каталога
провайдеров (`docs/research/tool-providers-2026-11.md` → данные в коде с датой проверки).

## Маршрутизация, повторы и отказы

Для каждой возможности сервер перебирает включённые ключи по приоритету. Ошибки делятся на
классы, и только класс уходит модели, не текст провайдера:

| Класс | Признаки | Действие |
|---|---|---|
| `transient` | 408, 429 с `Retry-After`, 5xx, таймаут, обрыв | повтор с экспоненциальной паузой и джиттером (как у LLM), затем следующий ключ |
| `quota_exhausted` | 402, 429 с признаком квоты, `insufficient_quota`, исчерпан `monthly_limit` | ключ помечается `exhausted_until`, следующий ключ без повтора |
| `auth` | 401, 403 | ключ помечается недействительным, следующий ключ, пользователю — уведомление в настройках |
| `unsupported` | 413, 415, формат или длина не принимаются | другой провайдер или деградация (кадры вместо видео, порции вместо целого) |
| `fatal` | прочее | остановка инструмента |

Для каждого ключа есть автомат-предохранитель (circuit breaker): после N подряд отказов ключ
отключается на время, и прогон не тратит повторы на заведомо мёртвый адрес.

**Реализовано:** `services/capability_router.py`, пороги и паузы — в `config.py`
(`CAPABILITY_*`). Отказ источника сохраняет структурный результат в `derivation.params.routing`
и понятный текст ошибки; `services/capability_incidents.py` (`TechnicalQuestionIncidentSink`)
создаёт из него неблокирующий технический вопрос проекта через `TechnicalQuestionService`
(квота → `quota_exhausted`, отказ ключа → `credential_invalid`, несовместимый материал/нет
возможности → `capability_missing`). Временный и фатальный сбой вопроса не создают.

Модель получает структурный результат:
`{status: "unavailable", reason: "quota_exhausted", capability: "speech_to_text",
done: "00:00–34:10", remaining: "34:10–80:00", alternatives: ["vision:frames"]}`.
Дальше она решает сама: продолжить с тем, что есть, использовать запасной путь или задать
технический вопрос.

## Технические вопросы

Бизнес-вопросы (`QuestionKind`) касаются процесса и влияют на граф. Технические касаются
материалов и запуска, на граф не влияют и в IR не попадают. Отдельная категория
`question_category = technical`:

| Тип | Пример |
|---|---|
| `quota_exhausted` | «У распознавания речи закончилась квота: не расшифровано 46 из 80 минут записи “Совещание 12.10”.» |
| `credential_invalid` | «Ключ “Exa (личный)” отклонён провайдером.» |
| `capability_missing` | «Страницы 12–18 — сканы, а OCR и модель с чтением PDF не подключены.» |
| `budget_reached` | «Бюджет прогона $10 исчерпан на этапе сверки вопросов.» |
| `input_incomplete` | «Видео без звуковой дорожки: распознано только по кадрам.» |

У технического вопроса есть действия, а не текстовый ответ: «Открыть настройки», «Повторить»,
«Продолжить без этого», «Поднять бюджет». Повтор не платит дважды: готовые производные
источники и сегменты кешируются (см. ниже). Блокирующий технический вопрос останавливает
прогон в состоянии «ждёт пользователя». Неблокирующий попадает в предупреждения, а модель
отмечает в допущениях, что часть материала не прочитана (`analysis_input_complete=false`, как в
ADR-0012).

### Что реализовано (шаг 2)

- Домен: `QuestionCategory` (`business`/`technical`), `TechnicalQuestionKind` (пять типов),
  `QuestionActionKind` (открыть настройки, повторить, продолжить без этого, поднять бюджет) и
  поля `Question` — `category` (по умолчанию `business`), `actions`, `blocking`. Миграция
  `0019_technical_questions`: категория, действия (JSONB) и блокирующий флаг с ограничением
  значений.
- `services/technical_questions.py` — единственная точка создания технических вопросов
  (`create`, `report_failure`) и действий по ним (`POST /questions/{id}/actions`). Это контракт
  для волны инструментов: квоты, неверный ключ, отсутствующая возможность и неполный ввод
  передаются сюда структурно (`CapabilityFailure`), не текстом ошибки провайдера.
- Технические вопросы не попадают в контекст модели, сверку бизнес-вопросов и IR: их отсекает
  `ingest/context.py` и сервис прогонов; сводка вопросов их не считает.
- Блокирующий вопрос переводит прогон в `RunStatus.waiting`: частичный уникальный индекс
  `uq_runs_active_project` пересоздан с учётом `waiting`, второй прогон по проекту начать
  нельзя; SSE остаётся открытым (событий `done` нет), подпись этапа — «Ждёт вашего действия».
  `POST /runs/{id}/resume` продолжает прогон (с первого этапа), закрывая открытые вопросы
  прогона как неактуальные. `POST /questions/{id}/actions` выполняет действие и продолжает
  прогон: «поднять бюджет» объединяет бюджет профиля монотонно вверх, «повторить» и
  «продолжить без этого» продолжают ожидающий прогон. Завершение, ошибка и отмена прогона
  переводят его технические вопросы в `obsolete`; «Повторить» предлагается только при
  связанном прогоне (у вопроса из фоновой обработки медиа прогона нет).
- Бюджет профиля — `RunProfile.budget {tokens?, cost_usd?}` (RFC-0005, шаг 5): проверяется перед
  каждым запросом к модели по накопителю прогона (включая потраченное до продолжения после
  `waiting`). Достигнутый бюджет — мягкая остановка: `waiting` и блокирующий вопрос
  `budget_reached`, а не ошибка. Бюджет в деньгах требует известных цен модели; на
  демонстрационной модели бюджет отклоняется (422).
- Кеша производных источников ещё нет: продолжение после технического вопроса повторно
  выполняет этапы, поэтому может снова оплатить запрос модели. Статус `waiting` не
  восстанавливается автоматически после рестарта — прогон остаётся ждать действия пользователя,
  а не начинает платную работу сам.

## Производные источники

Всё, что система получила из исходного файла, становится отдельным источником с родителем:

```
demo-crm.mp4                         (пользователь)
├── звуковая дорожка                 (файл, не текст)
│   └── расшифровка [мм:сс] + говорящие   (ИИ · Deepgram · $0,42)
├── ключевые кадры (37)              (ИИ · смена сцены)
│   └── описание экрана по кадрам    (ИИ · Claude Haiku 5.5)
├── общая лента «речь + экран»       (ИИ · сведено кодом)
└── краткое содержание               (ИИ · не используется как основание)
```

Новые поля `Source`: `origin` (`user`, `derived`, `agent`, `answer`), `parent_id`,
`derivation` (`capability`, `provider`, `model`, параметры, стоимость, время), `trust`,
`edited_by_human`, `revision`.

**Уровни доверия.** От них зависит, что можно цитировать в основаниях IR:

| `trust` | Что это | Основание для IR |
|---|---|---|
| `primary` | текст и документы пользователя, ответы на вопросы | да |
| `extracted` | расшифровка, OCR, текст страницы — машинное, но сверяемое с исходником | да, с ссылкой на таймкод или страницу |
| `observed` | описание кадров, событий видео | да, с пометкой «по изображению» и таймкодом |
| `external` | результаты поиска и публичные страницы | да, с URL и датой; ниже приоритетом при конфликте |
| `agent` | материалы внешних агентов (RFC-0007) | да, с указанием, кто и через какой токен |
| `summary` | краткие содержания, обзоры | **нет**: только навигация, цитаты из них не принимаются |

Правка человеком производного источника создаёт новую ревизию, и она важнее версии ИИ (как
ручные правки схемы). Цитаты, указывавшие на старую ревизию, нужно пересвязать. Это зависит от
ревизий оснований (#34), поэтому реализуются вместе.

Кеш: производный источник адресуется хешем `(parent hash, capability, provider, model,
params)`. Повторный прогон и повтор после технического вопроса не платят за уже сделанное.

## Видео

1. `ffprobe`: длительность, наличие звука и видео.
2. Звук — как сейчас (ADR-0012), но через `speech_to_text` с перебором ключей; говорящие
   включаются, если провайдер их умеет.
3. Кадры: ffmpeg выбирает смены сцены (`select='gt(scene,T)'`) и добавляет кадр не реже
   раза в N секунд; почти одинаковые кадры отбрасываются по перцептивному хешу. Порог и шаг —
   из профиля обработки.
4. Кадры пачками уходят в `vision` (рабочая модель). Если подключён `video_understanding`,
   модель может вместо этого отдать видео целиком.
5. Код сводит общую ленту: `[12:30] Иван: «отправляем на согласование» | Экран: карточка
   заявки, кнопка «Согласовать» неактивна`.

Профили обработки — «только звук», «звук + редкие кадры», «подробно». Перед обработкой
показывается оценка (минуты распознавания, число кадров, ориентировочная цена). Модель в
агентном режиме может попросить подробнее конкретный отрезок (`analyze_video(range=…)`).
**Полноту гарантирует код:** каждая секунда звука либо расшифрована, либо помечена как
необработанная, каждый отрезок видео либо покрыт кадрами, либо помечен. Модель решает, где
смотреть глубже, а не что пропустить.

На слабой VPS ffmpeg работает с параллельностью 1 и временной папкой, удаляемой всегда (как
сейчас). Кадры хранятся уменьшенными, срок хранения настраивается.

## Плейбуки по типам материалов

Системный промпт собирается из базовых правил генерации (`generation-quality.md`) и плейбука
типа материала: «запись совещания» (говорящие, решения, «кто делает что»), «демо интерфейса»
(экраны, действия пользователя, системные задачи), «регламент» (роли, сроки, условия), «таблица
или выгрузка» (статусы и переходы), «веб-страница» (дата и источник, пониженное доверие).
Плейбуки лежат в коде с версией, проверяются через `prompt-eval`, выбираются по типу источника
и подтверждаются моделью при чтении оглавления.

## Оркестратор и рабочие модели

В агентном режиме (RFC-0004) сильная модель планирует и собирает схему, а чтение порций,
описание кадров и черновые выдержки отдаёт рабочей модели из профиля (RFC-0005). Инструмент
`delegate(task, inputs, budget)` запускает рабочие запросы параллельно в пределах
`parallel_requests` и бюджета. Сервер проверяет результаты рабочих моделей так же, как
результаты основной: дословные цитаты, таймкоды в пределах записи. Свой цикл, а не Managed Agents
Anthropic: нужны те же проверки, журнал `llm_calls` и независимость от провайдера.

## Интерфейс

- Слева — дерево материалов: исходные файлы, производные узлы со статусом, стоимостью и меткой
  «ИИ».
- Справа — содержимое выбранного узла с правкой; для записи — плеер, который перематывается на
  таймкод цитаты.
- «Журнал решений» прогона: что сделано (какие инструменты, сколько стоило), какие вопросы
  сняты и почему, какие допущения приняты, что не прочитано. Клик по элементу схемы ведёт к
  основаниям, а от основания — к моменту записи или странице.
- Технические вопросы — отдельная вкладка рядом с бизнес-вопросами, с действиями.

## Как внедрять

1. ✅ Обобщённые ключи и маршрутизация с классами ошибок; первым переведено существующее
   распознавание речи (ветка `feature/wave-2-tools-keys`). Остались адаптеры vision/OCR/видео/веба
   и вызовы инструментов моделью.
2. ✅ Технические вопросы (заодно для бюджета из RFC-0005); отказы инструментов создают их
   через `TechnicalQuestionIncidentSink`.
3. Производные источники: `parent_id`, `origin`, `trust`, кеш; дерево в интерфейсе.
4. Сканы PDF через модель или `ocr` для страниц из `unreadable_pages`.
5. Кадры видео + `vision`, общая лента, плеер с таймкодами.
6. `web_search` / `web_fetch` в агентном режиме.
7. Ревизии производных источников вместе с #34.

## Риски

- **Конфиденциальность.** Записи совещаний энергокомпании уходят третьим сторонам. В проекте
  нужна политика «какие провайдеры разрешены» (например, только LLM-провайдер, или только
  провайдеры с размещением данных в РФ). По умолчанию новые инструменты для проекта выключены,
  пока владелец их не разрешит.
- **Внедрение инструкций через страницы и кадры.** Текст с веб-страницы или экрана — данные.
  Инструменты чтения не меняют проект; итог проходит те же проверки.
- **Стоимость и квоты.** Оценка до обработки, лимиты на ключ, кеш производных.
- **Диск VPS.** Медиа и кадры занимают место; срок хранения и, позже, объектное хранилище.

## Не входит

Локальные модели распознавания, OCR и vision на сервере; встроенный браузер с логином
пользователя; распределённая очередь обработки.
