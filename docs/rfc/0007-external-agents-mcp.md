# RFC-0007. Внешние агенты: MCP-сервер, токены доступа и проверка коллегой

- Дата: 2026-11-04
- Статус: принято; шаг 1 реализован (токены доступа и вход по `Authorization: Bearer` в REST,
  см. [auth-and-sharing.md](../backend/auth-and-sharing.md#токены-доступа-для-агентов)); шаги 2–4
  не реализованы
- Связано: [RFC-0001](0001-architecture.md), [RFC-0006](0006-tools-connectors-and-derived-sources.md),
  [ADR-0001](../adr/0001-auth-and-project-sharing.md), [ADR-0011](../adr/0011-user-llm-credentials.md),
  [auth-and-sharing.md](../backend/auth-and-sharing.md)

## Зачем

Часть материала сервер получить не может: Confluence, внутренние порталы, системы, где процесс
выполняется, страницы за логином. Доступ к ним есть у пользователя и у его собственного агента
(Claude Code, Claude Desktop, другой клиент MCP): у агента есть браузер пользователя, корпоративные
коннекторы и скиллы. Вместо встроенного браузера с чужими сессиями продукт открывается агенту:

1. **Сбор материала.** «Зайди в Confluence, выгрузи страницы отдела продаж про согласование
   договоров и добавь в проект BPMN Space “Договоры”». Агент сам ходит по закрытым системам, при
   желании обрабатывает тяжёлые медиа у себя и загружает в проект источники и производные
   материалы.
2. **Полный цикл.** Агент создаёт проект, загружает материалы, запускает анализ, отвечает на
   вопросы, которые знает из контекста, запускает сборку, читает результат и замечания линтера.
3. **Проверка коллегой.** Аналитик отправляет коллеге ссылку: «проверь свою часть схемы». Коллега
   просит своего агента: «посмотри дорожку “Казначейство” и ответь на вопросы по ней». Агент
   читает схему и вопросы этой дорожки, сверяется с тем, что знает, и записывает ответы.

## Варианты

| Вариант | Плюсы | Минусы |
|---|---|---|
| Только REST + OpenAPI (уже есть) | ничего не делать | вход через cookie и CSRF, нет описаний инструментов для агента, агент угадывает порядок вызовов |
| **Удалённый MCP-сервер + персональные токены** | любой клиент MCP подключается одной командой; инструменты описаны для модели; общий слой сервисов с REST | новая поверхность атаки, нужна модель прав |
| WebMCP (страница сама отдаёт инструменты агенту в браузере) | работает в сессии пользователя | ранняя стадия, поддержка браузеров не устоялась |
| Расширение браузера | доступ к открытым вкладкам | отдельный продукт, проверка магазинами |

Решение: **удалённый MCP-сервер (Streamable HTTP) на `/mcp` в том же backend и персональные
токены доступа.** REST остаётся основным контрактом; MCP — тонкий слой над `services/`.
К WebMCP вернёмся, когда он стабилизируется.

## Персональные токены

Настройки → «Доступ для агентов»:

- Создание: название («Claude Code на ноутбуке»), права, проекты (все или выбранные), срок
  (по умолчанию 30 дней, максимум год, как у ссылок). Токен показывается один раз с готовой
  командой подключения.
- Хранение: таблица `api_tokens`, только SHA-256 (как у сессий), префикс для опознания
  (`bps_…`), `last_used_at`, `revoked_at`. Это не `access_tokens`: у сессий нет прав и проектов.
- Права:

| Право | Что разрешает |
|---|---|
| `projects:read` | список проектов, схема, версии, вопросы, источники, журнал прогонов |
| `projects:write` | создать проект, переименовать, сохранить правку схемы (с `base_version_id`) |
| `sources:write` | добавить, изменить источник |
| `sources:delete` | удалить источник |
| `runs:start` | запустить анализ и сборку **на ключах моделей владельца токена**; оценка стоимости обязательна |
| `questions:answer` | ответить на вопрос, отметить «не применимо» |

- Ключи моделей и инструментов через токен не выдаются и не перечисляются; агент видит только
  «какие модели доступны» и профили (RFC-0005).
- Лимиты частоты — на токен, бюджет `expensive` для запусков, журнал действий в проекте:
  «Источник добавлен агентом “Claude Code на ноутбуке” (Мария)».

Подключение (пример для Claude Code):

```bash
claude mcp add --transport http bpmn-space https://<домен>/mcp --header "Authorization: Bearer bps_…"
```

OAuth 2.1 для MCP, как рекомендует спецификация для удалённых серверов, — следующий шаг, когда
понадобится вход без копирования токена.

## Инструменты MCP

| Инструмент | Право | Заметки |
|---|---|---|
| `list_projects`, `get_project` | read | сводка: дорожки, число узлов, открытые вопросы, последний прогон |
| `create_project` | write | |
| `list_sources`, `read_source(id, from, to)` | read | порциями, как в RFC-0004 |
| `add_source(kind, title, text \| url \| file)` | sources:write | файл — через одноразовую ссылку загрузки, не base64 в аргументе; `origin=agent` |
| `update_source`, `delete_source` | sources:write / delete | удаление помечено как разрушающее, требует `confirm: true` |
| `list_questions(lane?)`, `answer_question` | read / answer | |
| `estimate_run`, `start_run(kind, profile)`, `get_run` | runs:start / read | `start_run` без свежей оценки отклоняется |
| `get_diagram(lane?)` | read | XML, сводка IR и основания выбранной дорожки |
| `check_diagram(xml)` | read | XSD и bpmnlint без сохранения |
| `save_diagram(xml, base_version_id)` | write | те же правила конфликтов и ручных правок, что в интерфейсе |

Ресурсы MCP: `project://{id}/diagram.bpmn`, `project://{id}/questions`. Подсказки (prompts):
«Собери материалы по процессу», «Проверь мою дорожку».

## Материалы от агентов

Всё, что пришло через токен, — источник с `origin=agent` и `trust=agent` (RFC-0006): кто,
каким токеном, когда, по какой ссылке или системе получено (если агент сообщил). В дереве
материалов у таких узлов своя метка. Ответ на вопрос через агента записывается как ответ
владельца токена с пометкой «через агента»: сервер не может проверить, читал ли человек ответ
перед отправкой, и не делает вид, что может.

## Проверка коллегой

Ссылка проверки — новая роль ссылки `reviewer` рядом с `viewer` и `editor`
(auth-and-sharing.md):

- Область: проект целиком или выбранные дорожки; права — чтение схемы и оснований, ответы на
  вопросы области, комментарии.
- Коллега открывает ссылку в браузере или нажимает «Подключить своего агента». Тогда создаётся
  токен на его аккаунт с правами `projects:read` + `questions:answer` только для этого проекта
  и этой области, со сроком ссылки.
- Без аккаунта и MCP: кнопка «Скопировать запрос для агента». Готовый текст содержит описание
  дорожки, шаги, основания и открытые вопросы. Коллега вставляет ответ агента в форму, и тот
  становится ответом с пометкой «через агента».

Аналитик видит ответы коллег по дорожкам, а следующий прогон учитывает их как обычные ответы
(ADR-0006): с основаниями и приоритетом над допущениями.

## Безопасность

- Токены — только хеш в БД; отзыв мгновенный; срок обязателен.
- Минимальные права по умолчанию: чтение и ответы; удаление — отдельное право.
- Внедрение инструкций: текст, пришедший от агента, — данные источника. Модель продукта не
  выполняет из него команд; изменения проекта проходят те же проверки, что из интерфейса.
- Стоимость: `start_run` требует оценки и уважает бюджет профиля; агент не может поднять бюджет
  выше настроенного пользователем.
- Утечки: ответы MCP не содержат ключей, внутренних адресов и тел ответов провайдеров.
- Редакторы и наблюдатели получают через MCP не больше, чем в интерфейсе (`ensure_project_access`).

## Как внедрять

1. `api_tokens`, раздел настроек, вход по `Authorization: Bearer` в существующих REST-маршрутах.
   Уже это даёт агентам полный доступ по OpenAPI. **Реализовано** (миграция `0017_api_tokens`):
   права проверяются объявлением `require_scope` у маршрута, маршрут без объявления по токену
   закрыт. Журнал действий агента в проекте и пометка «через агента» у ответов — ещё нет.
2. MCP-сервер на `/mcp` поверх `services/` (Python MCP SDK, Streamable HTTP), инструменты из
   таблицы, e2e-сценарий «агент создаёт проект и собирает схему» в `e2e-agent`.
3. Роль ссылки `reviewer` с областью-дорожками, «Скопировать запрос для агента».
4. «Подключить своего агента» по ссылке проверки и OAuth.

## Не входит

WebMCP, расширение браузера, встроенный браузер с сессией пользователя, публичный каталог
MCP-серверов.
